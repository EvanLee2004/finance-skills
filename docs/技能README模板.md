# 技能 README 统一模板（每个业务技能都照这个写）

> **读者**：写/改 skill 的人和 agent。
> **为什么要统一**：同事、领导、接手的人打开 `skills/<id>/README.md` 就该看懂
> **这技能能干吗、原来手工怎么干、现在人和 AI 怎么配合干**——不用翻代码、不用问人。
> **铁律**：技能的处理逻辑/判定分支/输入输出/口径一变，**同一个 commit 里把 README 和图改到与代码一致**。
> 判据：一个没看过代码的人只读这份 README，会不会对"现在到底怎么跑"产生错觉——会就得改。

---

## 必写的三段（这是本模板的核心，缺一不可）

| 段 | 回答什么 | 写给谁看 |
|---|---|---|
| **① 这个技能干嘛** | 一句话说清它替代了哪件活、产出什么 | 所有人 |
| **② 没有它的时候怎么做** | 她**原来手工**怎么一步步干、卡在哪、多久 | 领导 / 接手的人 / 评估价值 |
| **③ 现在怎么用** | 她**说哪句话** → AI 做什么 → **停在哪等她拍板** → 她拿到什么 | 同事 / agent |

②③ 是这份模板跟普通 README 最大的区别：**不写"手工原样"，就没人说得清这技能到底省了什么、
也没人能判断自动化后有没有漏掉她原来会做的动作。**

## 写作要求

1. **数字要真**：验收口径里的例数、金标数字必须是**跑出来的**，不许写"预计"。
2. **边界要诚实**：`已知边界` 写清楚**不做什么**；文档把计划写成现状 = 骗人。
3. **面向同事的话用大白话**：README 里给同事看的段落不写脚本名、E 码、参数。
4. **图与逻辑同 commit**：见顶部铁律。
5. **通用基座技能**（`docx` / `pdf` / `pptx` / `xlsx`）不套本模板全套——
   它们不是财务业务活，README 说清「能处理什么文件、给哪些业务技能打下手、来源与许可」即可。
