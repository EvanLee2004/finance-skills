## 一、取数：只有一个入口

财务管理 →「**回款记录**」，主快照按目标核销日筛。
然后把每笔回款记录**点进去的明细页**抓下来。父回款只出现在最新一次核销日：
每天正常做不会漏；补跑历史日时，如果父记录已因再次核销移到新日期，就从累计子明细按真实核销日还原，
再补取对应父回款、SO、SOD。同一 SO 的首款和尾款可能落在不同父 AR；取数还要按 SO
查询全局核销明细，补齐目标日前的未撤销历史行，累计时不得按当前 AR 分组截断。

```
回款记录（1 笔到账）
  ├─ 关联「下单」                    → 这笔关联了哪几个 SO + 每个 SO 的交付额
  ├─ 关联「订单同币种核销明细信息」  → 逐 SO 的本次核销金额
  │                                    ⚠ 0 行 = 全额核销（明妹原话：没有这张就说明到账=交付）
  │                                    ⚠ 该子表是**累积**的，必须按本次核销日期过滤
  │                                    ⚠ 表里没有叫 SO 的字段，SO 在关联字段「订单NUM」里
  │                                    ⚠ 「是否已撤销=是」的行不算数
  └─ 由 SO 去「订单明细」表          → 每个 SO 下的 SOD + 逐 SOD 交付额
                                       **SOD 的唯一来源**；她盈亏表一行 = 一个 SOD
```

### 已废弃：按核销日期单独筛「回款核销对账」表

三条理由（2026-07-23 实调）：

1. **它对预存/预收类返回 0 行**。旧版靠"按回款类型走三条通道"来补，而通道路由正是
   2026-07-22 **静默丢 3 笔到账 6.5 万**的根因（预收类既被踢出对账通道、又在明细子表
   拿不到行，两头落空还不报错）。
2. **它拿不到 SOD 与逐 SOD 交付额**，判不出"一个 SO 拆 N 个 SOD"这个主场景。
3. 它是独立筛的第二张表，与回款记录可能不同步；关联读法天然同步。

> 顺带销掉一条旧卡点：「同币种核销明细」用陆总账号 `getFilterRows` **直查 0 行**，
> 但用 `getRowRelationRows` **关联读得到**。这不是账号权限问题，是查法问题。

## 二、判定

```
每笔到账：
  P[so] = 同币种核销明细逐 SO 本次核销金额
          有“本次核销金额本币”优先使用；否则直接使用“本次核销金额”
          该表本次 0 行 → P[so] = 该 SO 最新交付额（全额核销）
  R[so] = 截至目标核销日、同一 SO 跨父 AR 的累计核销金额
  D[so] = SO/SOD 最新实际交付额

  ── 手续费字段完全忽略，不加、不减、不分配、不做币种或范围闭环
  ── 父到账额不用于替代 P[so]，也不作为逐 SO 核销金额的上限
  ── 有 P[so] 就不因缺父回款汇率或父子币种文本不同挂起
  ── 校验 每笔到账至少产出 1 条判定，否则**整体报错退出**（防静默丢 AR）
  ── 校验 每个来源 AR/SO 都进入 auto/hold/exception，否则**整体报错退出**（防同 AR 漏订单）

  每个 SO：
    lines = 订单明细[SO]（SOD + 交付额）
    P[so] == Σlines  → 该 SO 全部 SOD 入选，每个填自己的交付额
    否则             → 在 lines 里凑**唯一**子集；多解/无解/行太多 → E5 挂起并列候选
    lines 为空       → 退化按 SO 匹配盈亏表（仍可判，不是丢单）
```

订单交付额为空时：只有该 SO 的全部 SOD 金额完整、唯一、非空，才允许用 SOD 合计回补；
任何一行缺金额都保持 E7，不推测。补跑漏日/连续多日时，
`audit_shifted_details.py --date-from … --date-to …` 将迁移键与历史判定结果对账；
缺键的真实核销日重新生成增补《核销日清》，仍须人工确认后写入。正常日清不追扫全历史。

## 三、盈亏表定位（她表里一行 = 一个 SOD）

优先级：

1. **SO + 应收金额** ← 主键。回填前后都成立（应收金额 = 该 SOD 交付额）
2. **SOD** ← 她已回填过「实收金额」列时可用（幂等重跑走这条）
3. **SO 唯一行**
4. 同一 SO 下多行金额相同 → 试**整段逐位对齐**：
   她这个 SO 的全部行（行号升序） vs 智云该 SO 的全部 SOD（编号降序），
   金额序列**逐位完全相等**才算对齐（两边都源自月初同一份「交付数据」，天然同序）。
   有一位对不上就老实挂 E8。
5. 都不行 → 表里找不到这单：SO 是往年的 → E3 跨年老单；否则 E2 还没交付。
   **注意顺序：先查表、查不到才判 E3**。2025 年的单在 2026 表里有行是常态。

## 四、五列怎么填

| 列 | 值 |
|---|---|
| 计提金额 | 累计回款达到最新实际交付金额时填该交付金额；未达到时，已收/未收两行都留空 |
| 回款明细 | 实际回款金额；多笔最终合计应等于最新实际交付金额 |
| 差异 | 仅最终结清且原始应收≠最新实际交付额时，按实际行列写公式“应收金额-计提金额”并保存缓存值；部分回款阶段两行都留空 |
| 是否结账 | 完整核销「是」；部分核销的已收行「是」、未收行「否」 |
| 收款时间 | 不看回款类型：到账月=核销月填到账日期，到账月≠核销月填核销日期 |
| 收款方式 | 不看回款类型：到账月=核销月填“汇”，到账月≠核销月填“冲预收” |
| 实收金额 | 该 SOD 号 |

交付额变化或部分回款时：

- 盈亏表原始应收是历史基线 `B0`，拆行后应收合计必须仍为 `B0`。
- 最新实际交付 `D` 是计提和实际未收的真相源。
- 累计实际回款 `R`；实际未收 `U=D-R`。
- 同一 SO 跨父 AR 的历史核销要合并计入 `R`；同一 SOD 拆为多行时，原始应收基线 `B0`
  取拆分行应收合计，不取当前命中的单行应收。
- 未收行应收=`U`；已收侧应收合计=`B0-U`。禁止用旧应收直接减回款。
- 部分回款唯一命中 SOD 时，日清展示方案；确认后在对应未结清行正下方自动插入未回款行。
- 已回款行填本次回款、结账「是」、日期和方式；新增未回款行结账「否」，计提/回款/日期/方式留空。
- 五项一致但差异空时只补差异；差异也一致时幂等跳过；差异非空且错误时冲突，不覆盖。
- 只有本次需要业务值差异时才强制要求“差异”列；普通回款兼容没有该列的旧测试表。

> ⚠ 2026-07-23 删掉旧规则「预存/预收类 → 冲预收」。实测证伪：7-22 那天
> AR26070089/107/112 全是预存回款，她 15 行**全填「汇」**；她整张 2026 表 2921 行里
> 「冲预收」只有 175 行（6%），不可能等于预存类占比。旧规则会把这 15 行全填错。
