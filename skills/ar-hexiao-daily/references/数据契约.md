### 《核销日清》→ `今日清单` 每行

**第一列＝单号（SOD，无 SOD 时用 SO）**，**第二列＝状态**（今天要填 / 已填过·跳过 /
冲突·需你定 / 挂账待办 / 异常），第三列＝怎么办；后面是 SO / AR / 客户(打码) / 本次金额 /
`应填_业务值差异` / 五项回款应填 / `当前_业务值差异` / 五项回款当前 /
`当前值与计划值的比较差异` /
**怎么找到这行（按 SO 筛选）** / 流转表定位 / 判定依据 / 码。

三个“差异”概念必须分开：

- `应填_业务值差异`：业务表“差异”列的计划值 `B0-D`；
- `当前_业务值差异`：业务表“差异”列的当前缓存显示值；
- `当前值与计划值的比较差异`：审核说明，逐字段展示当前值与计划值的不同，不写入业务表。

### 累计与历史基线

- 原始核销行先按“核销记录NUM”去除跨快照物理重复；不同记录号先进入父 AR 条件重复审计。只有父回款明显超核销且同 SO、金额、币种的精确重复组全部折叠后恢复到 1 元容差内时，忽略每组除排序最小记录号外的记录；其他情况全部保留或整笔挂账。
- `cumulative_writeoffs[_local]` 按 SO 汇总**截至当前父回款步骤**的运行累计，允许来源跨父 AR；
  同一目标日有多笔父回款时，不得把日终最终累计复制给每一笔。核销记录按“核销日期、核销记录NUM、rowid、父 AR”确定顺序；缺核销记录NUM时禁止自动建立同日多父回款拆行链。
- 通过父 AR 条件重复审计后的合法逻辑记录按核销顺序跨父 AR 累计；被标记为 `system_duplicate_ignored` 的记录不得进入本次 `H` 或累计 `R`。
- 每条原始记录的 disposition 必须是 `kept`、`physical_snapshot_duplicate`、
  `system_duplicate_ignored` 或 `revoked`；任何无处置记录都使覆盖校验失败。
- 同一 SOD 普通拆行后的 `B0` 是该 SOD 全部拆分行业务应收合计。`D>B0` 的特殊拆行中，
  `B0` 是全部业务行中非空应收的合计：原始行保留 `B0`，后续已收行和未结清承接行应收为空。
  特殊计划使用 `receivable_mode=preserve_baseline_blank_carry`，并分别保存
  `baseline_receivable`、`source_row_receivable` 和仅供判断的 `remaining_unreceived`。
  最终结清时 `derived_cols.差异 = B0-D`；不得以当前目标单行应收代替 `B0`，也不得把空应收当成 `0` 写回。
- 上传表仅作为离线差异验收输入，不属于本契约的运行输入；不得生成参考表覆盖标记，
  不得把已有非空不同值从 conflict 改成 write。

**禁止用行号定位盈亏**（她随时插行，行号隔天失效）。流转写入可用「文件#sheet 第N行」（流水行稳定于本次副本）。

### `流转写入计划_校验后.json` schema（2026-07-25）

```json
{
  "items": [
    {
      "ar": "AR…",
      "file": "到账流转….xlsx",
      "sheet": "明细",
      "row_no": 12,
      "hits": 1,
      "matched_by": "三键",
      "so_entries": [
        {"so": "SO1", "delivery_amount": 10000.00},
        {"so": "SO2", "delivery_amount": 20000.00}
      ],
      "order_suggest": "SO1  10,000.00\\nSO2  20,000.00",
      "updated_suggest": "是",
      "red_sos": [],
      "verdict": "write",
      "reason": ""
    }
  ],
  "counts": { "write": 0, "hand": 0, "skip": 0 }
}
```

- `verdict=write`：强三键唯一命中；分类后可前置写 SO+交付金额，状态须等盈亏实际写入与回读完成后再写
- `verdict=hand`：须她手填（弱/0/多命中或定位失败）  
- `verdict=skip`：无建议内容可跳过
