### 《核销日清》→ `今日清单` 每行

**第一列＝单号（SOD，无 SOD 时用 SO）**，**第二列＝状态**（今天要填 / 已填过·跳过 /
冲突·需你定 / 挂账待办 / 异常），第三列＝怎么办；后面是 SO / AR / 客户(打码) / 本次金额 /
`应填_业务值差异` / 五项回款应填 / `当前_业务值差异` / 五项回款当前 /
`当前值与计划值的比较差异` /
**怎么找到这行（按 SO 筛选）** / 流转表定位 / 判定依据 / 码。

三个“差异”概念必须分开：

- `应填_业务值差异`：业务表“差异”列的计划值 `B0-D`；
- `当前_业务值差异`：业务表“差异”列的当前缓存显示值；
- `当前值与计划值的比较差异`：审核说明，逐字段展示当前值与计划值的不同，不写入业务表。

### 累计与历史基线

- `cumulative_writeoffs[_local]` 按 SO 汇总截至目标日的全局核销明细，允许来源跨父 AR；
  当前父 AR 只负责承载本次任务，不能截断历史累计。
- 同一 SOD 拆行后的 `B0` 是该 SOD 全部拆分行业务应收合计。最终结清时
  `derived_cols.差异 = B0-D`；不得以当前目标单行应收代替 `B0`。
- 上传表仅作为离线差异验收输入，不属于本契约的运行输入；不得生成参考表覆盖标记，
  不得把已有非空不同值从 conflict 改成 write。

**禁止用行号定位盈亏**（她随时插行，行号隔天失效）。流转写入可用「文件#sheet 第N行」（流水行稳定于本次副本）。

### `流转写入计划_校验后.json` schema（2026-07-25）

```json
{
  "items": [
    {
      "ar": "AR…",
      "file": "到账流转….xlsx",
      "sheet": "明细",
      "row_no": 12,
      "hits": 1,
      "matched_by": "三键",
      "order_suggest": "SO1\\nSO2",
      "updated_suggest": "是",
      "verdict": "write",
      "reason": ""
    }
  ],
  "counts": { "write": 0, "hand": 0, "skip": 0 }
}
```

- `verdict=write`：确认后 `apply_flow` 可写（强三键唯一命中）  
- `verdict=hand`：须她手填（弱/0/多命中或定位失败）  
- `verdict=skip`：无建议内容可跳过
