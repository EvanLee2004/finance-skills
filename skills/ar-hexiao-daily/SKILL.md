# 应收核销日清（人在环 · SOD 级 · 一次确认两表写入）

**主战场从第 6 步开始**（明妹钉死）：智云按核销日筛 → 判定 → 校验 → 流转计划 → **《核销日清》** → ★停 → 她确认 → **先盈亏明细、后流转安全子集**。  
1–4 她提才做；第 5 步销售不绑隔天。

**取数只有一个入口**：财务管理 →「回款记录」，主表按目标核销日筛，再抓每笔明细（下单 / 同币种核销明细 / 订单明细 SOD）。  
**最新核销日显示机制**：父回款记录只出现在最新一次核销日。每天正常按日做不会漏；如果漏跑历史日，父记录后来又核销而移到新日期，则从累计子明细按真实核销日还原，生成增补日清。同一 SO 的前后两次回款可能属于不同父 AR，取数必须按 SO 全局补取截至目标日的历史核销，累计时不得再按当前 AR 隔断。  
**「回款核销对账」已废弃**（预存静默丢单）。

**数据源**：第 6 步智云 = 核销金额真相；流转表 = 备份 + 单号 + 是否更新，**金额不从流转推**。  
**写表**：盈亏只动「明细」；流转确认后只改「单号」「是否更新应收款」（强三键唯一命中）。  
**永不写智云。** 金额只由 `scripts/*.py` 算。

**交付额变动口径（2026-07-29）**：

- 盈亏表原始应收是历史基线；智云最新实际交付额 `D` 是计提与剩余应收真相源。
- 部分回款实际未收 `U = D - 累计实际回款 R`，禁止用旧应收减回款。
- 人工拆行后原始应收合计必须保持不变：未收行应收=`U`，已收侧应收合计=`原始应收合计-U`。
- 回款明细写本次实际回款。部分回款在人工确认后自动把当前未结清行转为已回款行，并在其正下方新增未回款行。
- 累计回款 `R < D` 时两行计提都留空；只有 `R = D` 时，最后结清行计提填 `D`。
- 最终结清且原始应收 `B0 ≠ D` 时，原始应收不改，差异列写公式“应收金额-计提金额”，
  同时无损保存缓存值 `B0-D`（保留到分，不得按有效数字截断或舍入）；公式必须按写入后的实际行列动态生成。
  应收与本次核销不一致时必须先查该 SO 的最新实际交付额再判断结清或拆行。
- `R` 优先按智云同一 SO/SOD 截至目标日的累计核销明细计算；本次核销只是本次回款明细，不能替代累计值。同一 SO 跨父 AR 的历史核销也必须合并。
- 逐 SO 核销金额无法唯一落到多个 SOD 时，按盈亏“明细”行号从小到大选择该 SO 的首个未结清 SOD；金额不足则按部分回款拆行。首行不能安全承接（无未结清行、缺交付额、累计超收或拆行不守恒）时继续挂账，禁止跨多个 SOD 自动摊分。分笔回款已有逐 SO 核销金额时走同一规则；只有缺逐 SO 金额时才挂 E1。
- 核销明细先按“核销记录NUM”识别同一物理记录的跨快照重复；不同记录号即使 AR、日期、SO、金额相同，也必须先保留为不同原始记录。缺记录号时禁止用业务字段冒充物理唯一键。
- 每个父 AR 先按统一币种口径计算 `delta_raw=父到账金额-原始未撤销核销合计`。本币完整时用本币；否则仅在父子同币种时用原币；所有金额先规范到分，手续费完全忽略。
- 只有 `delta_raw < -1.00` 才检查同一父 AR 内“SO＋核销金额＋币种口径”的系统重复；原币和本币同时存在时两者都要一致。折叠后 `delta_dedup >= -1.00` 才允许恢复为 auto，并带 `W_SYSTEM_DUPLICATE_WRITEOFF_COLLAPSED`；被忽略记录同时从本次 `H` 和累计 `R` 排除。
- 明显超核销无法由精确重复完全解释、缺核销记录NUM或金额/币种不可比时，整笔父 AR 以 `E_SYSTEM_OVER_WRITEOFF_UNRESOLVED` 挂账，不得部分自动写入。
- 同一 SOD 已经拆成多行时，`B0` 是这些拆分行应收的合计，不是本次命中的单行应收；由此判断是否需要业务值差异。
- 智云有逐 SO“本次核销金额本币”时优先使用；没有本币列但有“本次核销金额”时直接使用，
  不再反向要求父回款汇率，也不因父回款与订单币种文本不同挂起。
- **盈亏表金额统一为人民币本币**：外币订单在没有逐 SO 核销明细时，交付额、计提和回款明细
  必须按订单行汇率换算为本币（优先使用智云本币金额）；禁止把 USD 等原币数直接写入盈亏表。
- 手续费字段完全忽略：不加、不减、不分配、不参与核销范围或币种闭环判断，且不再产生
  `E_FEE`。回款明细以智云逐 SO“本次核销金额”为准；无逐 SO 明细仍按智云语义视为全额核销，
  以最新实际交付额落到 SO/SOD。
- 禁止用 SO/AR 白名单、点名单号或上传盈亏表改变本次核销金额。上传表只用于写后离线差异分析，
  用来发现规则缺口，不能覆盖智云判定、已有非空值或冲突。
- 细则见 `config/业务规则.md`。

## 0.4 ★ 先把「哪一天」说死（每次开跑第一件事）

**这条链路有两个互不相干的日期，混了就是做错账：**

| 日期 | 是什么 | 驱动哪几步 |
|---|---|---|
| **到账日期** | 钱哪天到的银行 | 第 1–4 步（日记账 / 挑收入 / 流转表 / 建回款） |
| **核销日期** | **销售哪天在智云把这笔钱核到订单上** | **第 6 步起的主战场（本技能默认说的就是它）** |

她的口径原话：「与建回款无固定隔天关系；核了就进那个核销日，没核就进更后的日期」
→ **两者天然不是同一天**，可能差好几天。所以：

1. **先查漏天**：`batch_ledger.py gaps`。有从没跑过的核销日 → **先报给她**，
   建议从最早那天开始一天一批补（`--date 那天`）。
   > 为什么必须查：`--date yesterday` 是相对**运行那天**算的。她周一跑取的是周日（销售周末不核销、必空批），
   > 周二跑取周一——**中间漏掉的那几天永远没人管，程序一声不吭**。请假、出差、故障同理。
   > 漏一天 = 那天的到账永远不会回填进盈亏表，事后也看不出来。
2. **复述给她确认，等她回话再取数**（她指令里已经说了日期就不再问，只复述）：
   ```
   我按**核销日期 2026-07-24（周五）**来跑 —— 就是销售在这一天核销的那些到账，对吗？
   （另外 7-22、7-23 这两天从来没跑过，要不要等这批完了接着补？）
   ```
3. **一次只跑一个核销日**。禁止把几天合成一批：混批会让 AR 覆盖率校验、幂等校验
   和她对着清单逐行核对**全部失真**（她核的是"这一天的到账"）。程序也会直接拒绝。
   **要补多天 → 你自己跑多遍，见 §0.45**，不是把几天塞进一批。
4. **取数 0 笔 ≠ 出错**：那天销售一笔没核销就是空批，如实说「这天没有核销，已记台账」，
   别让她以为没跑成。
5. **正常日清不会因后续再次核销而漏**：原核销日当时已经处理；只有历史日没跑或旧判定结果缺键时才启动迁移还原。

**所有产出（判定结果 / 日清 / 文件名）一律按核销日命名**，不按"跑的那天"——
她补跑 7-22 时若按运行日命名，会跟今天那批撞名甚至盖掉。

## 0.45 补多天：先规划 → 短句确认 → 一天一天跑几遍

**她不是天天来**（约一周两天，看她哪天有空），一来往往积了好几天的核销。
处理办法是**你多跑几遍**，不是把几天合成一批。

**顺序钉死：从早到晚。** 因为同一个订单可能**分两天核销**（7-21 核一半、7-23 核另一半），
两笔填的是她表里**同一行**——先跑早的写进去，晚的那天再来时才看得到"已经填了一半"
接着算；顺序反了或并成一批，两笔会抢同一行、双双挂起，等于白跑。

**你的动作**：
1. `batch_ledger.py gaps` 列出要跑哪几天
2. **一句话报计划给她**（别长篇）：
   ```
   有 3 天没跑：7-21、7-22、7-23。我从早到晚一天一天来，每天出一份清单你点头我再写。开始？
   ```
3. 她点头 → **依次跑**：第 1 天走完整主路径（判定→日清→她确认→写入）→ 再跑第 2 天……
4. 每天开头报一句进度：`第 2 天 / 共 3 天 · 核销日期 2026-07-22（周三）`
5. 中间她喊停就停，剩下的天留在台账里，下次 `gaps` 还会报出来（不会丢）

⛔ 不许为了省事把几天并批；⛔ 不许跳过中间某天直接跑最新的那天。

## 0.46 父记录按最新核销日迁移：补跑时还原

智云父回款只显示在最新一次核销日；子表保留每个订单各自的历史核销日。

1. **每天正常做**：只跑当天目标核销日；后续再核销不会让已经写过的历史行丢失，不做全历史追扫。
2. **补跑漏日/连续多日**：对明确日期范围跑 `audit_shifted_details.py --date-from … --date-to …`。
3. 报告 `needs_rerun=true` 的日期从早到晚逐日重跑 `classify → validate → worklist`；程序从更新日期文件的累计子明细还原原核销日。
4. 幂等校验跳过已写行，只把新增/冲突行放进增补清单；仍须她确认，禁止绕过确认闸。
5. 只有本次目标日来源覆盖 `AR/SO = 100%` 才允许说“这天完整”。

> ⚠ **顺序钉死：`validate_plan` 必须在 `build_worklist` 之前**（清单状态以校验为准）。  
> ⚠ **`build_flow_plan` 在日清前跑**（或由 worklist 自动生成）；日清要展示流转自动写 M / 手填 K。

## 0.5 硬禁止

1. 禁止自写 Python 读她的 Excel；只准调 `scripts/`。  
2. 禁止把客户名、金额明细打进对话。  
3. 缺输入就停下报缺，禁止凑合。  
4. **禁止跳过《核销日清》直接 apply**（无 `--confirmed` 脚本拒绝）。  
5. **未确认时禁止写盈亏、禁止写流转**；确认后流转**仅**强三键唯一命中（`hits==1` 且 matched_by 为三键/三键含手续费），弱命中/0/多命中手填。  
6. **禁止把「判不出来」悄悄跳过**：每笔到账及其每个 AR/SO 都必须进入 auto/hold/exception；两级覆盖率不过立即退出。  
7. 禁止写智云；禁止改流转金额/日期；除“唯一命中 SOD”或“按已确认规则选中同 SO 首个未结清 SOD”的部分回款外禁止自动插行。  
8. **禁止不说日期就开跑**：每次必须先定「核销日期 = 哪一天」并复述确认（§0.4）。  
9. **禁止把多个核销日合成一批**（程序会拒；确要混批须她明确点头）。  
10. **禁止在写入失败/复核没过时"绕过去再试一次"**——那说明她的表在确认之后变了，
    正确动作是**重出一份日清让她重新确认**，不是加参数硬写。

## 0.6 怎么跟她说话

**短 · 像人 · 主动要料。** 一两句说完；她是出纳不是程序员，长篇大论她不看。
缺输入别干等——一次列清要她给什么。细则 → `references/跟明妹沟通.md`。

- ❌ 报脚本名/E 码/auto=143；❌ 解释原理；❌ 一次抛一堆问题  
- ✅ 「判完了：**盈亏今天要填 N、冲突 C；流转自动写 M、手填 F**。清单在 <路径>，你说确认我再写。」  
- ✅ 报计划也一句：「有 3 天没跑：7-21、7-22、7-23。从早到晚一天一天来，开始？」  
- 要问就**一次问一件**，给选项，别让她做填空题。

## 0.8 判不准就问她

同 SO 首个未结清 SOD 不能安全承接 / 大于 0.01 的尾差 / 跨年 → 带选项问。答案记 `config/业务规则.md`。

## 1. 红线

1. 金额只由脚本算。  
2. 对话不回显客户名金额。  
3. 分笔已有逐 SO 核销金额时正常落单；缺逐 SO 金额才 hold。禁止均分/比例分摊；同 SO 多 SOD 歧义只允许默认首个未结清 SOD，不得跨 SOD 自动摊分。日清必须按“最新交付额 − 累计实际回款”计算未收并保持原始应收合计不变。  
4. 永不写智云。  
5. 写盈亏只许「明细」；写前备份、写后回读。  
6. **回填 = 日清 → 她确认 → `apply_all --confirmed`（先盈亏后流转）**。  
7. 回填金额 = 第 6 步智云，不用流转表金额。  
8. 列名模糊匹配；找不到列 → 报错。  
9. **AR + AR/SO 两级来源覆盖率硬校验**；核销日清首页必须显示覆盖数、历史子核销还原行和交付额回补数。  
10. 盈亏失败 → **零**流转写入。

## 2. 工作区

### 2.0 写入副本的唯一基线（硬规则）

每次新跑或重跑，必须新建一个独立工作区，并且只从下列两份根目录测试文件复制出本次的
`02_我的表副本/`：

```
<盈亏权威基线.xlsx>
<到账流转测试副本.xlsx>
```

盈亏权威基线由用户指定的下载版建立；下载原件只读，稳定副本固定保存为上述“权威基线”。
禁止把任何已跑过、已写过、名称含“重跑/结果”的工作副本再作为下一轮写入起点；
文件夹名称和哈希相同不能替代五个业务字段的空值/原始值核验。复制后先记录两份根文件和
两份新副本的 SHA-256，确认副本与根文件一致，才能开始 `classify → validate → worklist → apply`。
根目录两份文件永远只读；所有写入、备份和变更清单只允许落在新工作区的副本中。

## 3. 流程编排（11 步）

### 3.1 主路径命令

**⚠ 照抄，别自己改路径、别加 `--workspace`。**
所有脚本默认就用技能自带的 `工作区/`，**不传最稳**。传了 `--workspace .` 这种相对路径，
产出会分家（判定落一处、日清落另一处），她说确认时流转计划找不到 → **只写盈亏、静默漏掉流转**。
（程序现在会自动纠正并喊一声，但别去踩。）她的表放在别处时，才传**绝对路径**。

```bash
cd "<本skill目录>"                # ← 只做这一件事，后面全用相对脚本名
HX=2026-07-24                     # ★ §0.4 复述并经她确认后才填
```

确认词：`确认` `OK` `ok` `可以写` `按这个写` `没问题写吧` `写吧`。

**写入前程序会自己再核一次**（她在"看清单 → 说确认"之间动过表就拒写）：

### 3.2 流转「是否更新」三态

| 状态 | 填法 |
|------|------|
| 全部订单都**没交付进表**(E2/E3) | **留空**（不要公式、不要「否」） |
| 全部都能更（**含部分核销 E5 拆行**）| **是** |
| 有的能更、有的没交付进表 | **部分**（没交付 SO 标红） |

自动写准入：`hits==1` 且强三键；只写单号 + 是否更新。实现：`build_flow_plan` / `apply_flow`。

### 开关

- `--flow-complete`：渠道表齐了才严判 E0  
- `--ledger`（rescan）：真重判挂起  
- `--confirmed`：人工确认后才写  
- `--in-place` / `--flow-in-place`：就地写（写前备份）

## 4. 你（agent）怎么干

1. **先定核销日**（§0.4）：查漏天 → 复述 → 等她确认。别默认"昨天"就开跑。
   要补多天 → §0.45：报计划 → **从早到晚一天一天跑几遍**，别并批。  
2. 盘点输入；正常日清不追扫全历史。补跑/多日任务必须按明确日期范围跑迁移审计，不能等她指出订单。  
3. 主路径跑到 **build_worklist** 停下，用 §0 照抄结尾（**含核销日期**与流转 M/F）。  
4. 等确认词 → `apply_all --confirmed`（禁止只写盈亏忘流转，也禁止颠倒顺序）。  
5. 写入前复核没过 → **重出日清让她重新确认**，不许硬写。  
6. 对话只报笔数/路径/成败/日期。

## 6. 已知边界（不许夸大）

- 分笔缺逐 SO 金额 / 大于 0.01 的尾差 / 同 SO 首个未结清 SOD 不能安全承接 / 跨年：hold。  
- 取数版本必须为 `2026-07-31-writeoff-record-identity-v1`；旧版或无版本标记的自动导出必须重新取数。明确接受的旧手工导出若缺“核销记录NUM”，正常余额仍可处理，但明显超核销只能挂账，不能自动纠重。
- 手续费完全不参与业务金额；逐 SO 本次核销金额原样使用，不做净额/含费识别或分配。  
- 有本次核销金额本币时优先使用；只有本次核销金额时直接使用。外币且无逐 SO 明细时，
  必须用订单汇率或可验证本币金额换算，拿不到则挂账，绝不把原币数字写进盈亏表。  
- 流转弱命中/多命中：**手填**，不自动写。  
- 拆行（E5）：日清按 `最新交付额 − 累计实际回款` 给方案；确认后在对应未结清行下方自动插入未回款行，并校验拆前拆后原始应收合计不变。  
- 插行时，所有被下移业务行的普通公式必须按原单元格→新单元格的 Excel 复制语义完整平移；相对行列随行移动，`$` 绝对引用保持。禁止只替换“公式所在行号”，也禁止只看旧缓存值判断公式正确。
- 单格 shared master 被复制为新行 follower 时，master `ref` 必须扩展覆盖新单元格；写出前逐组验证唯一 master、master/ref 一致和所有 follower 均位于 `ref` 内，任何一项失败都禁止落表。
- 只要目标工作簿的业务格、公式或行坐标发生变化，必须完整移除可重建的旧 `calcChain.xml` 及其关系声明，并设置 Excel 打开时全量重算；禁止保留指向旧行或已被常量覆盖单元格的过期计算链。
- 交付额变了：计提目标按智云最新交付额，回款明细按实际回款，盈亏表原始应收基线不覆盖；
  最终结清时差异列写公式“应收金额-计提金额”。  
- 部分回款：累计未达到最新交付额时，已回款行与新增未回款行的计提均留空；累计达到最新交付额时，只在最后结清行填计提=`D`。  
- 部分回款阶段两行“差异”都留空；已有非空差异时禁止静默覆盖。旧表没有“差异”列且本次不需要写差异时继续兼容。  
- 差异幂等：五项一致但差异空→只补公式；五项与差异都一致→跳过；差异非空但不一致→冲突。  
- 同一 SOD 拆成多行时，业务值差异比较使用这些行的应收合计 `B0`；不得拿最后一次命中的单行应收与 `D` 比较。
- 与上传版生成差异表时，已配对行的公式先按两侧真实单元格坐标平移后再比较。仅坐标平移等价的公式单独汇总，不列为错误；平移后仍不等价，以及公式与常量不同，必须进入“公式需复核”。
- 收款时间/方式不看回款类型：到账月=核销月时填到账日期 +「汇」；到账月≠核销月时填核销日期 +「冲预收」。
- **结账**：能走到 auto 的 SOD 任务已做 →「是」（不得用整笔回款「预存部分核销」状态否掉每个小单）。  
- **漏天检测的起点 = 台账第一次登记那天**，之前的历史不算漏（装上之前跑过的天要她自己认）。
- **周末默认不算该跑的日子**（`gaps` 会另行说明跳过了几个周末；要补加 `--all-days`）。
- **写入前复核只防"表被动过"**，防不了她把两份副本搞混——所以计划里记的是**文件路径 + 指纹**，
  换一份表就会报出来。
