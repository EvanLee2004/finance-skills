# 应收核销日清（人在环 · SOD 级 · 一次确认两表写入）

**主战场从第 6 步开始**（明妹钉死）：智云按核销日筛 → 判定 → 校验 → 流转计划 → **《核销日清》** → ★停 → 她确认 → **先盈亏明细、后流转安全子集**。  
1–4 她提才做；第 5 步销售不绑隔天。

**取数只有一个入口**：财务管理 →「回款记录」，**只筛核销日期 = T-1**，再抓每笔明细（下单 / 同币种核销明细 / 订单明细 SOD）。  
**「回款核销对账」已废弃**（预存静默丢单）。

**数据源**：第 6 步智云 = 核销金额真相；流转表 = 备份 + 单号 + 是否更新，**金额不从流转推**。  
**写表**：盈亏只动「明细」；流转确认后只改「单号」「是否更新应收款」（强三键唯一命中）。  
**永不写智云。** 金额只由 `scripts/*.py` 算。

## 0. 按她的话直接跳

| 她说的话 | 直接做 | 命令链 |
|---|---|---|
| 跑昨天的核销 / 出清单 / 日清 | **取数→判定→校验→流转计划→日清，然后停** | 见 §3.1 上半 |
| 确认 / OK / 可以写 / 按这个写 | **仅有日清后** `apply_all --confirmed` | 见 §3.1 下半 |
| 拉智云 / 导智云 | 取数进 01_ | `fetch_zhiyun.py` |
| 挑收入 / 日记账 | 第 2 步（次要） | `extract_income.py` |
| 挂账 / 重扫 / 空的和部分 | 重扫 | `rescan_holds.py --ledger …` |
| 我文件放好了 / 缺什么 | 盘点 | `inspect_inputs.py` |

**「跑昨天的核销」= 出到《核销日清》为止，禁止顺手 apply。**

> ⚠ **顺序钉死：`validate_plan` 必须在 `build_worklist` 之前**（清单状态以校验为准）。  
> ⚠ **`build_flow_plan` 在日清前跑**（或由 worklist 自动生成）；日清要展示流转自动写 M / 手填 K。

```
   · 盈亏：今天要填 N 行 · 已填过·跳过 S 行 · 冲突·需你定 C 行

🔒 智云没写、盈亏表没写、流转表也没写
👉 打开扫一眼；没问题回我「确认」或「可以写」，我再统一写：先盈亏明细，再流转可写笔（写前备份）
```

⛔ 禁止说「填进智云」。⛔ 禁止未确认就 apply。

## 0.5 硬禁止

1. 禁止自写 Python 读她的 Excel；只准调 `scripts/`。  
2. 禁止把客户名、金额明细打进对话。  
3. 缺输入就停下报缺，禁止凑合。  
4. **禁止跳过《核销日清》直接 apply**（无 `--confirmed` 脚本拒绝）。  
5. **未确认时禁止写盈亏、禁止写流转**；确认后流转**仅**强三键唯一命中（`hits==1` 且 matched_by 为三键/三键含手续费），弱命中/0/多命中手填。  
6. **禁止把「判不出来」悄悄跳过**：每笔到账必须产出判定，覆盖率不过报错退出。  
7. 禁止写智云；禁止改流转金额/日期；禁止自动插行。

## 0.6 怎么跟她说话

- ✅ 「判完了：**盈亏今天要填 N、冲突 C；流转自动写 M、手填 F**。清单在 <路径>，你说确认我再写。」

## 0.8 判不准就问她

SOD 凑不出唯一 / 一 SO 多行 / 手续费 / 尾差 / 跨年 → 带选项问。答案记 `config/业务规则.md`。

## 1. 红线

1. 金额只由脚本算。  
2. 对话不回显客户名金额。  
3. 分笔一律 hold，禁止均分/比例分摊。  
4. 永不写智云；账密不落盘。  
5. 写盈亏只许「明细」；写前备份、写后回读。  
6. **回填 = 日清 → 她确认 → `apply_all --confirmed`（先盈亏后流转）**。  
7. 回填金额 = 第 6 步智云，不用流转表金额。  
8. 列名模糊匹配；找不到列 → 报错。  
9. **AR 覆盖率硬校验**。  
10. 盈亏失败 → **零**流转写入。

## 3. 流程编排（11 步）

每步三句：`✅ 做完了` / `📁 路径` / `👉 下一步 + 触发词`。

| 步 | 名称 | 谁做 | 入口 |
|----|------|------|------|
| 1–4 | 日记账→挑收入→流转→建回款 | **她做**（次要） | 不提别串 |
| 5 | 销售核销 | 销售 | 不绑隔天 |
| **6** | 智云取数（核销日=T-1） | `fetch_zhiyun` 或她导 | → `01_` 四件套 |

### 3.1 主路径命令

```bash
SKILL="<本skill目录>"
WS="$SKILL/工作区"
LEDGER="$WS/02_我的表副本/<盈亏副本.xlsx>"

python3 "$SKILL/scripts/fetch_zhiyun.py"    --date yesterday --workspace "$WS"
python3 "$SKILL/scripts/verify_sources.py"  snapshot --workspace "$WS"
python3 "$SKILL/scripts/inspect_inputs.py"  --workspace "$WS"
python3 "$SKILL/scripts/classify_hexiao.py" --workspace "$WS"
python3 "$SKILL/scripts/validate_plan.py" \
  --plan "$WS/04_产出/判定结果_*.json" --ledger "$LEDGER" \
  --out "$WS/04_产出/写入计划_校验后.json"
python3 "$SKILL/scripts/build_flow_plan.py" --workspace "$WS"
python3 "$SKILL/scripts/build_worklist.py"  --workspace "$WS"
# ★ 停。把《核销日清》给她。禁止继续 apply。

# 仅当她说「确认/OK/可以写/按这个写」：
python3 "$SKILL/scripts/apply_all.py" \
  --checked "$WS/04_产出/写入计划_校验后.json" \
  --flow-plan "$WS/04_产出/流转写入计划_校验后.json" \
  --ledger "$LEDGER" --workspace "$WS" \
  --confirmed --in-place --flow-in-place
# 头几次可去掉 --in-place / --flow-in-place，出新文件并排验

python3 "$SKILL/scripts/verify_sources.py" verify --workspace "$WS"
```

确认词：`确认` `OK` `ok` `可以写` `按这个写` `没问题写吧` `写吧`。  
她说改/跳过 → 改计划、**重新出日清**再确认。

### 3.2 流转「是否更新」三态

| 状态 | 填法 |
|------|------|
| 全部订单都**没交付进表**(E2/E3) | **留空**（不要公式、不要「否」） |
| 全部都能更（**含部分核销 E5 拆行**）| **是** |
| 有的能更、有的没交付进表 | **部分**（没交付 SO 标红） |

自动写准入：`hits==1` 且强三键；只写单号 + 是否更新。实现：`build_flow_plan` / `apply_flow`。

### 开关

- `--flow-complete`：渠道表齐了才严判 E0  
- `--ledger`（rescan）：真重判挂起  
- `--confirmed`：人工确认后才写  
- `--in-place` / `--flow-in-place`：就地写（写前备份）

## 4. 你（agent）怎么干

1. 盘点输入；缺料一次说清。  
2. 主路径跑到 **build_worklist** 停下，用 §0 照抄结尾（含流转 M/F）。  
3. 等确认词 → `apply_all --confirmed`（禁止只写盈亏忘流转，也禁止颠倒顺序）。  
4. 对话只报笔数/路径/成败。  
5. 依赖：`pip install openpyxl xlrd`；智云另需 requests/playwright。  
6. 测试：`python3 -m pytest tests/ -v`（应 ≥150 例全绿）。

## 6. 已知边界（不许夸大）

- 分笔 / 手续费 / 尾差 / SOD 歧义 / 跨年：hold。  
- 流转弱命中/多命中：**手填**，不自动写。  
- 拆行（E5）：日清给方案，**不自动插行**。  
- 交付额变了：按智云额 + ⚠。  
- 计提：回满智云交付额才填；结账与计提两套判据。  
- **结账**：能走到 auto 的 SOD 任务已做 →「是」（不得用整笔回款「预存部分核销」状态否掉每个小单）。
