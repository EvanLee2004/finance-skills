# 应收核销日清（人在环 · SOD 级 · 一次确认两表写入）

**主战场从第 6 步开始**（明妹钉死）：智云按核销日筛 → 判定 → 校验 → 流转计划 → **《核销日清》** → ★停 → 她确认 → **先盈亏明细、后流转安全子集**。  
1–4 她提才做；第 5 步销售不绑隔天。

**取数只有一个入口**：财务管理 →「回款记录」，**只筛核销日期 = T-1**，再抓每笔明细（下单 / 同币种核销明细 / 订单明细 SOD）。  
**「回款核销对账」已废弃**（预存静默丢单）。

**数据源**：第 6 步智云 = 核销金额真相；流转表 = 备份 + 单号 + 是否更新，**金额不从流转推**。  
**写表**：盈亏只动「明细」；流转确认后只改「单号」「是否更新应收款」（强三键唯一命中）。  
**永不写智云。** 金额只由 `scripts/*.py` 算。

## 0. 按她的话直接跳

| 她说的话 | 直接做 | 命令链 |
|---|---|---|
| 跑昨天的核销 / 出清单 / 日清 | **先定日期(§0.4)** → 取数→判定→校验→流转计划→日清，然后停 | 见 §3.1 上半 |
| 跑 X 月 X 号的核销 / 补上周的 | 同上，日期用**她说的那天**（仍复述一次） | `--date <那天>` |
| 把没跑的都跑了 / 这几天的一起做 | **§0.45**：列出哪几天 → 一句话报计划 → **从早到晚一天一天跑几遍** | 每天走一遍 §3.1 |
| 确认 / OK / 可以写 / 按这个写 | **仅有日清后** `apply_all --confirmed` | 见 §3.1 下半 |
| 哪几天没跑 / 有没有漏 | 查漏天 | `batch_ledger.py gaps` |
| 拉智云 / 导智云 | 取数进 01_ | `fetch_zhiyun.py --date <核销日>` |
| 挑收入 / 日记账 | 第 2 步（**按到账日，不是核销日**） | `extract_income.py` |
| 挂账 / 重扫 / 空的和部分 | 重扫 | `rescan_holds.py --ledger …` |
| 我文件放好了 / 缺什么 | 盘点 | `inspect_inputs.py` |

**「跑昨天的核销」= 出到《核销日清》为止，禁止顺手 apply。**

## 0.4 ★ 先把「哪一天」说死（每次开跑第一件事）

**这条链路有两个互不相干的日期，混了就是做错账：**

| 日期 | 是什么 | 驱动哪几步 |
|---|---|---|
| **到账日期** | 钱哪天到的银行 | 第 1–4 步（日记账 / 挑收入 / 流转表 / 建回款） |
| **核销日期** | **销售哪天在智云把这笔钱核到订单上** | **第 6 步起的主战场（本技能默认说的就是它）** |

她的口径原话：「与建回款无固定隔天关系；核了就进那个核销日，没核就进更后的日期」
→ **两者天然不是同一天**，可能差好几天。所以：

1. **先查漏天**：`batch_ledger.py gaps`。有从没跑过的核销日 → **先报给她**，
   建议从最早那天开始一天一批补（`--date 那天`）。
   > 为什么必须查：`--date yesterday` 是相对**运行那天**算的。她周一跑取的是周日（销售周末不核销、必空批），
   > 周二跑取周一——**中间漏掉的那几天永远没人管，程序一声不吭**。请假、出差、故障同理。
   > 漏一天 = 那天的到账永远不会回填进盈亏表，事后也看不出来。
2. **复述给她确认，等她回话再取数**（她指令里已经说了日期就不再问，只复述）：
   ```
   我按**核销日期 2026-07-24（周五）**来跑 —— 就是销售在这一天核销的那些到账，对吗？
   （另外 7-22、7-23 这两天从来没跑过，要不要等这批完了接着补？）
   ```
3. **一次只跑一个核销日**。禁止把几天合成一批：混批会让 AR 覆盖率校验、幂等校验
   和她对着清单逐行核对**全部失真**（她核的是"这一天的到账"）。程序也会直接拒绝。
   **要补多天 → 你自己跑多遍，见 §0.45**，不是把几天塞进一批。
4. **取数 0 笔 ≠ 出错**：那天销售一笔没核销就是空批，如实说「这天没有核销，已记台账」，
   别让她以为没跑成。

**所有产出（判定结果 / 日清 / 文件名）一律按核销日命名**，不按"跑的那天"——
她补跑 7-22 时若按运行日命名，会跟今天那批撞名甚至盖掉。

## 0.45 补多天：先规划 → 短句确认 → 一天一天跑几遍

**她不是天天来**（约一周两天，看她哪天有空），一来往往积了好几天的核销。
处理办法是**你多跑几遍**，不是把几天合成一批。

**顺序钉死：从早到晚。** 因为同一个订单可能**分两天核销**（7-21 核一半、7-23 核另一半），
两笔填的是她表里**同一行**——先跑早的写进去，晚的那天再来时才看得到"已经填了一半"
接着算；顺序反了或并成一批，两笔会抢同一行、双双挂起，等于白跑。

**你的动作**：
1. `batch_ledger.py gaps` 列出要跑哪几天
2. **一句话报计划给她**（别长篇）：
   ```
   有 3 天没跑：7-21、7-22、7-23。我从早到晚一天一天来，每天出一份清单你点头我再写。开始？
   ```
3. 她点头 → **依次跑**：第 1 天走完整主路径（判定→日清→她确认→写入）→ 再跑第 2 天……
4. 每天开头报一句进度：`第 2 天 / 共 3 天 · 核销日期 2026-07-22（周三）`
5. 中间她喊停就停，剩下的天留在台账里，下次 `gaps` 还会报出来（不会丢）

⛔ 不许为了省事把几天并批；⛔ 不许跳过中间某天直接跑最新的那天。

> ⚠ **顺序钉死：`validate_plan` 必须在 `build_worklist` 之前**（清单状态以校验为准）。  
> ⚠ **`build_flow_plan` 在日清前跑**（或由 worklist 自动生成）；日清要展示流转自动写 M / 手填 K。

### 判定跑完 · 结尾照抄（一个字别改）

```
✅ 核销日期 <YYYY-MM-DD（周X）> 的核销判定完了，你的表还一个字节没动
📁 《核销日清》：<核销日清_YYYYMMDD.xlsx>  ← 只看这一份就够
   · 盈亏：今天要填 N 行 · 已填过·跳过 S 行 · 冲突·需你定 C 行
   · 挂账待办 H 行 · 异常 K 行
   · 流转：确认后将自动写 M 笔 · 须你手填 F 笔
   · 第一列是单号，第二列是状态，「怎么办」写了每行该干嘛
🔒 智云没写、盈亏表没写、流转表也没写
👉 打开扫一眼；没问题回我「确认」或「可以写」，我再统一写：先盈亏明细，再流转可写笔（写前备份）
⏰ 期间**先别动盈亏表和流转表**——你改了我这份清单就作废，得重出一份（程序会拦住不让写歪）
```

⛔ 禁止说「填进智云」。⛔ 禁止未确认就 apply。⛔ 禁止不说是哪个核销日就开跑。

## 0.5 硬禁止

1. 禁止自写 Python 读她的 Excel；只准调 `scripts/`。  
2. 禁止把客户名、金额明细打进对话。  
3. 缺输入就停下报缺，禁止凑合。  
4. **禁止跳过《核销日清》直接 apply**（无 `--confirmed` 脚本拒绝）。  
5. **未确认时禁止写盈亏、禁止写流转**；确认后流转**仅**强三键唯一命中（`hits==1` 且 matched_by 为三键/三键含手续费），弱命中/0/多命中手填。  
6. **禁止把「判不出来」悄悄跳过**：每笔到账必须产出判定，覆盖率不过报错退出。  
7. 禁止写智云；禁止改流转金额/日期；禁止自动插行。  
8. **禁止不说日期就开跑**：每次必须先定「核销日期 = 哪一天」并复述确认（§0.4）。  
9. **禁止把多个核销日合成一批**（程序会拒；确要混批须她明确点头）。  
10. **禁止在写入失败/复核没过时"绕过去再试一次"**——那说明她的表在确认之后变了，
    正确动作是**重出一份日清让她重新确认**，不是加参数硬写。

## 3. 流程编排（11 步）

> 指的多半是今天/昨天到的账；说"跑核销"指的是销售某天核销的那批。**别把两个日期串成一个。**

### 3.1 主路径命令

**⚠ 照抄，别自己改路径、别加 `--workspace`。**
所有脚本默认就用技能自带的 `工作区/`，**不传最稳**。传了 `--workspace .` 这种相对路径，
产出会分家（判定落一处、日清落另一处），她说确认时流转计划找不到 → **只写盈亏、静默漏掉流转**。
（程序现在会自动纠正并喊一声，但别去踩。）她的表放在别处时，才传**绝对路径**。

```bash
cd "<本skill目录>"                # ← 只做这一件事，后面全用相对脚本名
HX=2026-07-24                     # ★ §0.4 复述并经她确认后才填

# ① 先看有没有漏掉的核销日（有就先报给她，一天一批补）
python3 scripts/batch_ledger.py    gaps

# ② 取数。**这天的四件套已经在 01_智云导出/ 里就会自动跳过**（她手导的也算）。
#    要登录时它会当场问她账密——⛔ 你（AI）绝不替她输、绝不写进命令行或环境变量。
#    不在内网 / 非交互环境跑不了这步：那就让她手导四张表放进 01_智云导出/，直接跳到 ③。
python3 scripts/fetch_zhiyun.py    --date "$HX"
python3 scripts/verify_sources.py  snapshot
python3 scripts/inspect_inputs.py
python3 scripts/classify_hexiao.py --hexiao-date "$HX"   # 数据不是这天就退出，防取错日子
python3 scripts/validate_plan.py                          # 判定结果与盈亏副本自动找
python3 scripts/build_flow_plan.py
python3 scripts/build_worklist.py
# ★ 停。把《核销日清》给她。禁止继续 apply。

# 仅当她说「确认/OK/可以写/按这个写」：
python3 scripts/apply_all.py \
  --checked 工作区/04_产出/写入计划_校验后.json \
  --ledger  工作区/02_我的表副本/<盈亏副本.xlsx> \
  --confirmed --in-place --flow-in-place
# 流转计划不传会自动取 工作区/04_产出/流转写入计划_校验后.json
# 头几次可去掉 --in-place / --flow-in-place，出新文件并排验

python3 scripts/verify_sources.py verify
```

确认词：`确认` `OK` `ok` `可以写` `按这个写` `没问题写吧` `写吧`。  
她说改/跳过 → 改计划、**重新出日清**再确认。

**写入前程序会自己再核一次**（她在"看清单 → 说确认"之间动过表就拒写）：
盈亏比**指纹 + 每行 SO/SOD 身份**，流转比**命中行的日期/公司/金额**。
报「写入前复核没过」= 她的表变了 → **重跑 validate + build_worklist 出新清单让她再确认一次**，
⛔ 不许加参数硬写、不许只跳过报错那条（插一行会让它之后的全部错位）。

### 3.2 流转「是否更新」三态

| 状态 | 填法 |
|------|------|
| 全部订单都**没交付进表**(E2/E3) | **留空**（不要公式、不要「否」） |
| 全部都能更（**含部分核销 E5 拆行**）| **是** |
| 有的能更、有的没交付进表 | **部分**（没交付 SO 标红） |

自动写准入：`hits==1` 且强三键；只写单号 + 是否更新。实现：`build_flow_plan` / `apply_flow`。

### 开关

- `--flow-complete`：渠道表齐了才严判 E0  
- `--ledger`（rescan）：真重判挂起  
- `--confirmed`：人工确认后才写  
- `--in-place` / `--flow-in-place`：就地写（写前备份）

## 4. 你（agent）怎么干

1. **先定核销日**（§0.4）：查漏天 → 复述 → 等她确认。别默认"昨天"就开跑。
   要补多天 → §0.45：报计划 → **从早到晚一天一天跑几遍**，别并批。  
2. 盘点输入；缺料一次说清。  
3. 主路径跑到 **build_worklist** 停下，用 §0 照抄结尾（**含核销日期**与流转 M/F）。  
4. 等确认词 → `apply_all --confirmed`（禁止只写盈亏忘流转，也禁止颠倒顺序）。  
5. 写入前复核没过 → **重出日清让她重新确认**，不许硬写。  
6. 对话只报笔数/路径/成败/日期。  
7. 依赖：`pip install openpyxl xlrd`；智云另需 requests/playwright。  
8. 测试：`python3 -m pytest tests/ -v`（应 ≥186 例全绿）。

- 漏天可查：跑过 7-20、7-23 后 `batch_ledger gaps` 能报出 7-21/7-22。  
- **金标 2026-07-22**：157 SOD 行级基线、可填与她手填一致路径不倒退。

## 6. 已知边界（不许夸大）

- 分笔 / 手续费 / 尾差 / SOD 歧义 / 跨年：hold。  
- 流转弱命中/多命中：**手填**，不自动写。  
- 拆行（E5）：日清给方案，**不自动插行**。  
- 交付额变了：按智云额 + ⚠。  
- 计提：回满智云交付额才填；结账与计提两套判据。  
- **结账**：能走到 auto 的 SOD 任务已做 →「是」（不得用整笔回款「预存部分核销」状态否掉每个小单）。
- **漏天检测的起点 = 台账第一次登记那天**，之前的历史不算漏（装上之前跑过的天要她自己认）。
- **周末默认不算该跑的日子**（`gaps` 会另行说明跳过了几个周末；要补加 `--all-days`）。
- **写入前复核只防"表被动过"**，防不了她把两份副本搞混——所以计划里记的是**文件路径 + 指纹**，
  换一份表就会报出来。
