# 业务规则参数（可改）

> 改完参数后重跑脚本即可，不必改 Python。  
> **2026-07-23 明妹口径**：日常主战场从「第 6 步智云筛核销」起；回填只动盈亏「明细」；流转待办=空+部分。

## 批次

- **筛日**：按**核销日期**筛（常用昨天；当天核销还在变，默认不做当天）
- **与「建回款」无固定隔天关系**：销售何时核销我们不管；核了就进该核销日，没核就进更后的日期
- **当前年**：默认 2026（跨年老单判定用）

## 日期口径（2026-07-25 立·两个日期别混）

| 口径 | 含义 | 驱动 |
|---|---|---|
| **到账日期** | 钱哪天到银行 | 第 1–4 步（日记账/挑收入/流转表/建回款） |
| **核销日期** | 销售哪天在智云把钱核到订单上 | **第 6 步起（本技能默认口径）** |

| 规则 | 内容 |
|---|---|
| 开跑第一件事 | `batch_ledger.py gaps` 查漏天 → **复述日期给她确认** → 才取数 |
| 默认建议日 | 有空档 = **最早那个没跑过的日子**；没空档 = 上一个工作日（周一不取周日） |
| 一批一天 | **禁止多个核销日混一批**（覆盖率/幂等/她逐行核对全会失真）；程序直接拒绝 |
| **她的节奏** | **不天天来**：约一周两天、看她哪天有空，一来常积好几天的核销（2026-07-25 明昊确认） |
| **补多天** | **agent 多跑几遍**，不并批；**顺序从早到晚**（同一订单可能分两天核销、填同一行，先早后晚才接得上）；先一句话报计划给她点头，再一天一天走 |
| 命名 | 判定结果 / 日清 / 台账**一律按核销日**，不按运行日（补跑才不会撞名盖掉） |
| 空批 | 那天没人核销 = 正常收工，记台账、别当成出错，也别反复当漏天提醒 |
| 漏天起点 | 台账第一次登记那天；周末默认不计入（`--all-days` 可算上） |
| 最新核销日迁移 | 父回款只显示在最新核销日；每天正常做不会漏，补跑历史日时从累计子明细按真实核销日还原 |
| 完整标准 | 本次目标日 AR 覆盖 100% + AR/SO 覆盖 100%；补跑范围内的迁移键均进入 auto/hold/exception |

## 最新核销日迁移与补跑还原（2026-07-29 修正）

1. 目录有多天四件套时，主回款/订单文件必须按指定 `--hexiao-date` 精确选择，禁止按文件名排序拿第一份。
2. 父回款按最新核销日显示：1 日正常做过，2 日再次核销后父记录移到 2 日，不代表 1 日漏单。
3. 正常每日流程不扫描全部历史。只有补跑漏日/连续多日时，按明确日期范围扫描累计子明细并与历史判定结果对账。
4. 补跑旧日时，若父记录已移到更新日期，则从更新日期文件找到父回款，并只取子表真实核销日=目标日的 SO 金额。
5. 历史结果缺 AR/SO 才列 `needs_rerun`；已进入 auto/hold/exception 的不重复提醒。
6. 重跑历史日仍遵守“一天一批”和人工确认闸。旧行由幂等校验跳过，新增/冲突行进入增补《核销日清》。
7. 订单交付额为空时，只允许在该 SO 的全部 SOD 金额完整、唯一、非空时用 SOD 合计回补，并记录来源；任何缺值继续 E7。
8. 覆盖率必须检查两级：每笔 AR 有判定、每个来源 AR/SO 进入 auto/hold/exception。同一 AR 只漏一个 SO 也整批失败。

## 写入前复核（2026-07-25 立）

从「出清单」到「她说确认」之间她可能动过表（月初贴交付插行、部分核销上方插行）。
按旧行号写 = 写到别人那一单上，而写后回读只证明"值写进去了"、证不出"写对了行"。

| 对象 | 写前复核什么 | 不过怎么办 |
|---|---|---|
| 盈亏明细 | 副本 **sha256 指纹** + 每行 **SO/SOD 身份** + 该行是否仍可写 | **整批拒写**，重出日清让她重新确认 |
| 到账流转 | 命中行的 **日期 / 公司名称 / 金额** | **整批不写流转**（只跳过那一条会把其后全写歪） |
| 写后回读 | 五列 **+ SOD** 逐格比对 | 不替换原件，临时结果留档 |

⛔ 复核没过时**不许加参数硬写**——那是她的表变了，不是程序出错。

## 数据源优先级（2026-07-23）

- **第 6 步智云导出 / 拉数** = 核销金额、类型、SO/SOD 的**真相源**
- **第 7 步流转表** = 线下备份 + 对到账写单号 +「是否更新应收款」状态；**不能**当核销金额来源
- **回填（原第 8/9 步）必须从第 6 步结果来**，不是从第 7 步「推」出来
- 父回款“下单”关联为空时，继续读取同一父回款的“结算”关联找 SO；两处都为空才按无关联订单处理。
- 写前若目标 SO/SOD 已有结账行，且同一订单/SOD 不存在拆分未结账行，则按“订单已写入/已结账”幂等跳过；无逐单金额的顺序分配同样先跳过该订单。

## 核销记录身份与逐单金额优先（2026-08-04）

1. **物理去重**：以“核销记录NUM”为物理身份，只去除同一记录号在多个快照中的重复。不同记录号先保留为不同原始记录；缺记录号时不得使用 `AR+日期+SO+金额` 代替物理身份。
2. **逐单金额优先并受父金额约束**：逐 SO“本次核销金额/本币”完整时使用本币；否则只在币种一致时使用逐 SO 原币金额。原始逐单合计未比父总到账多 1 元以上时全部保留；明显超额时才检查同一父 AR 内 SO、金额、币种完全一致的精确重复组，每组只保留核销记录NUM排序最小的一条。
3. 回款类型为“整笔回款”时，加载父回款后先标记该审计路径，待全部关联订单加载完成后，在父 AR 级核对父总到账与订单金额合计。优先使用所有订单的“订单已核销金额”；全部订单该字段都缺失时才使用完整、可比的订单交付额兜底。部分有值、部分缺失时禁止混算。首选或兜底口径不可比、字段不完整或绝对差额超过 1 元时，整笔父 AR 以 `E_PARENT_WRITEOFF_MISMATCH` 挂账，全部关联 SO 禁止进入 SOD 匹配和写表。交付额兜底通过后逐 SO 金额取各订单交付额，并记录 `W_WHOLE_PAYMENT_DELIVERY_FALLBACK`。
4. 非整笔回款明显超额时，只有精确重复组全部折叠后差额恢复到 1 元容差内，才能继续自动处理并记录 `W_SYSTEM_DUPLICATE_WRITEOFF_COLLAPSED`。没有精确重复组、折叠后仍超额、缺核销记录NUM或金额币种不可比时，以 `E_SYSTEM_OVER_WRITEOFF_UNRESOLVED` 整笔挂账。没有有效逐 SO 金额时才回退父回款总到账，并按交付额升序、从首个未结清订单续核。
5. 每条原始记录必须标记为保留、跨快照重复、系统重复忽略或撤销；系统重复忽略必须附精确重复组及折叠前后差额。控制台只输出非敏感计数。
6. 当前自动导出版本为 `2026-08-05-order-written-off-fallback-v2`。旧版或无版本标记的自动导出不得静默复用；旧手工导出缺记录号时不得自动建立多父回款拆行链。

## 写盈亏表（2026-07-23）

- **只改「明细」sheet**，其它 sheet 一个字节不许动
- 允许写她指定的**长期工作副本**（新文件输出仍保留）；原件对照用「其他 sheet 总数」
- 部分核销/交付额变动：唯一命中 SOD 时在日清给出拆行方案；确认后自动插行；**计提留空，不写 0**
- **回填硬闸**：`validate_plan` → 《核销日清》→ **她口头确认** → 统一写入（见下节）。无 `--confirmed` 脚本拒绝写入。

## 写后计算与便携副本（2026-08-06）

- 普通常量回填保留原计算链；插行或公式变化时，写入模块先保存精确公式缓存，再按全部公式格重建 `calcChain.xml`。
- 正式交付前必须验证每个公式都有缓存值、计算链存在，并将 `fullCalcOnLoad`、`forceFullCalc` 设为 0。任一项失败则不替换工作副本。
- 盈亏工作副本存在历史外链时，必须在同目录生成 `_便携版.xlsx`。便携版把外链公式固化为当前缓存值并删除 externalLinks；生成后校验外链公式、外链引用和外链部件均为 0，且固化前后显示值差异为 0。
- 长期工作副本保留历史外链；便携版只用于发送或换电脑查看，禁止作为下一轮核销写入基线。

## 确认后统一写入（2026-07-25 · 已知完美）

**用户路径**：判定+校验+流转计划 → **一份《核销日清》**（盈亏 N/S/C + 流转自动写 M / 手填 K）→ ★停 → 她说确认 → **先盈亏明细、后流转安全子集**。

| 规则 | 内容 |
|---|---|
| 确认次数 | **一次**（确认 / OK / 可以写 / 按这个写） |
| 写入顺序 | ① `apply_to_copy` 盈亏成功 → ② `apply_flow` 流转；盈亏失败则**零**流转写入 |
| 未确认 | 盈亏与流转 **均禁止写** |
| 流转只改两列 | **单号**、**是否更新应收款**（不改金额/日期/公司名） |
| 流转可写准入 | `hits==1` 且 `matched_by`∈{三键, 三键(含手续费)}；弱命中/0/多命中 = **hand 手填** |
| 是否更新空白 | 建议留空 → 写入空字面，**不要写「否」**、不要公式 |
| 失败 | 备份+回读；失败不替换原件；该项报告 hand/失败 |

入口：`apply_all.py --confirmed`（或文档化的双命令且 agent 只推这一条主路径）。

待办集合（重扫）：

- **空** → 要更新 / 重扫
- **部分** → 要更新 / 重扫（与空同等重要）
- **红色字体**（人眼）→ 未更新；月初贴交付后优先补

**三态判据（2026-07-24 明妹口径修正）**：只看这笔到账下的订单**今天能不能在盈亏表里更新**：

## 交付额变动 + 部分回款怎么拆行（2026-07-29 会议定稿）

先分清四个数：

- `B0` = 盈亏表目标业务行的**原始应收历史基线**；发生拆行时，各拆分行应收合计
  必须仍等于拆行前的原始应收合计
- `D` = 智云**最新实际交付金额**（核销与计提真相源，可因客户对账加减）
- `R` = 截至本次的**累计实际回款**
- `U` = 实际未收 = `D - R`

部分回款（E5）在《核销日清》中先展示方案，确认后执行：

1. **回款明细按实际收到的金额填**，最终各笔回款明细合计应等于 `D`。
2. 当前未结清行转为**本次已回款行**：应收=`当前未结清行应收-U`，计提留空，回款明细填本次实收，结账「是」，填日期和方式。
3. 在当前行**正下方新增未回款行**：其它字段复制，应收=`U`，计提/回款明细/日期/方式留空，结账「否」。
4. 所有已收侧应收合计应为 `B0-U`；拆行后应收合计必须仍为 `B0`。
5. 只有累计回款 `R=D` 时才填计提=`D`；最后一笔直接结清当前未回款行，不再新增应收为 0 的行。
6. `R` 取智云同一 SO/SOD 截至目标核销日的有效逐单核销明细，加上此前已成功写表且对应父 AR 没有逐单明细的父回款顺序分配台账。不得只看本次核销金额，也不得只依赖盈亏表“结账”状态。
   同一 SO 的历史回款即使属于不同父 AR，或先走父回款兜底、后续再出现逐 SO 明细，也必须合并后再累计；同一父 AR 后来取得逐单明细时排除其旧兜底记录，禁止双计。后续父回款从首个 `D-R>0` 的订单续核。
7. `R<D` 时已回款行和新增未回款行的“差异”都留空；目标表有“差异”列时显式保持空白，
   没有该列的旧测试表仍可处理不需要业务值差异的普通回款。
8. 结清差额 `U=D-R` 的绝对值不超过 `1.00` 元时视为业务一致：实际回款金额保持原值，
   记录精确差额和容差审计，不新增未回款行；绝对值超过 `1.00` 元才继续拆行或按超收规则挂起。

例：`B0=30000`、`D=31000`、首笔回款 `15000`：

- `U=31000-15000=16000`
- 未收行应收 `16000`
- 已收侧应收合计 `30000-16000=14000`
- 两侧应收仍合计 `30000`，但回款明细反映实际收到的 `15000`

> 若 `R>D`（交付额下降导致超收）、无法唯一确定承接回款的 SOD、拆行后出现负应收，
> 一律继续 hold；不得猜分摊或强行插行。

## 尾差

- **技术金额容差（元）**：`0.005`。用于流水金额匹配、实际核销金额守恒、分配台账、写前和写后回读；禁止放宽到 1 元。
- **分位尾差阈值（元）**：`0.01`。用于同一 SO/SOD 的分位金额判断。
- **业务结清容差（元）**：`1.00`。只用于整笔父回款业务闸、结清尾差、是否新增未回款行以及人工表离线业务对比。
- 差异报告必须同时保留精确差额、技术结果和业务结果；不能因为业务一致而删除真实差额。

## 手续费、税费和其他费用

- 父回款总到账金额 = 净到账金额 + 明确手续费 + 明确税费 + 明确其他费用。
- 有逐 SO“本次核销金额”时直接使用逐单金额；费用只做父回款总额审计，不再二次加到任何 SO/SOD。整笔回款仍须先通过父 AR 金额守恒检查。
- 非整笔回款没有逐 SO 金额时，总到账按交付额升序队列和每单剩余未收顺序分配；已结清订单跳过，首个未结清订单优先续核。
- 费用原币、本币均保留；外币费用没有明确本币时，只能使用父回款可验证的隐含汇率。仍无法形成统一本币或同币种原币口径则挂账。
- 费用为负数、同一父回款已成功分配后总到账或关联订单变化时挂账，不得覆盖历史分配。
- 同一父回款重跑复用既有分配；若部分回款拆分组的表内累计已收已经覆盖该分配，即使仍保留未结账行，也必须幂等跳过。该未结账行只承接后续新的父回款，禁止同一父回款再次占用。
- 有逐 SO 累计核销金额时，以该累计作为重跑真相；若同一 SOD 拆分组表内累计已收已经达到或超过目标累计，幂等跳过本次记录，不得再次拆分未结账承接行。
- 上传盈亏表只用于离线差异分析与回归验收，禁止作为判定输入或覆盖已有非空值。

## 外币本币金额

- 智云已给出“本次核销金额本币”时直接使用，不需要另找汇率。
- 智云只有“本次核销金额”时也直接作为业务金额，不再反向要求父回款汇率。
- 父回款币种与订单币种文字不同不能阻断逐 SO 核销。
- 原币与本币同时存在时保留两者并优先使用本币；只有本次核销金额时使用该字段。
- 盈亏核算表的计提、回款明细、应收相关计算统一使用人民币本币。外币订单在无逐 SO
  核销明细而按“全额核销”兜底时，必须按订单交付行汇率换算交付额和回款金额；优先使用
  智云明确的本币值。缺本币值且无可验证汇率时挂账，禁止直接写原币数。

## 计提金额口径（2026-07-29 会议更新）

- **计提目标 = 智云最新实际交付金额 `D`**，不是盈亏表原始应收 `B0`。
- 每次抓取都要检查 `D` 是否变化；变化时日清必须明确展示新计提目标。
- 一次性全额回款可自动写：计提=`D`、回款明细=实际回款（此时等于 `D`）、结账=是。
- 部分回款：日清显示 `D/R/U` 和两行拆分结果；确认后自动拆行，但两行计提均留空。
- 累计回款达到 `D`：最后结清行计提填 `D`，不再新增零余额行。
- 最终结清时若原始应收 `B0 ≠ D`：原始应收不覆盖；`差异`列写公式
  `应收金额-计提金额`。公式引用写入后的实际行号和实际列号，不得写死；XML 同时保存
  缓存值 `B0-D`，以便 WPS/Excel 尚未重算时直接显示。缓存金额必须用无损数值文本写入，
  保留到分，禁止使用默认六位有效数字格式造成大金额尾数舍入。若累计回款尚未达到 `D`，
  两行计提与差异都留空。
- 写前与写后幂等：
  - 五项回款字段一致、差异为空：`write`，只补差异公式和缓存值；
  - 五项与差异都一致：`skip`；
  - 差异已有非空错误值：`conflict`，禁止覆盖；
  - 本次必须写差异而目标表没有该列：`conflict`；
  - 本次不需要写差异时兼容没有该列的旧测试表。
- **禁止沿用旧规则“没回满就把实际未收算成旧应收减回款”**。
- 同一 SOD 已经拆为多行时，`B0` 取这些拆分行的应收合计；不得用本次命中的单行应收
  与 `D` 比较，否则会把实际已结清误判为业务值差异。

## 交付额中途变了：实际口径按智云、历史基线不覆盖（2026-07-29 更新）

明妹原话："要让他动脑子去检查交付额，别以我表里那个为准。判断上面交付额跟下面核销额一不一样，

- **计提目标 = 智云最新交付额；回款明细 = 实际回款**，两者不能再混成一个数。
- 盈亏表原始应收只作为历史基线，拆行后合计必须保持不变；**实际未收只按 `D-R` 算**。
- **应收与本次核销额对不上时必须查询该 SO 的最新实际交付额 `D`**：累计实际回款达到
  `D` 才正常结清，计提=`D`，原始应收不改，并回填差异=`B0-D`；仍未达到 `D` 则按部分回款拆行。
- **命中行后若 `D ≠ 她表应收`**：一律顶一个 ⚠ 到《核销日清》「怎么办」列，明确说明
  “计提按最新交付额、应收不改、差异写应收减计提”。
  以前只有「整段等比例差(×0.97)」会提醒，靠 SOD / SO 唯一行命中的（她没改过应收那几行）**闷声就填、不吭声**
  —— 实测 SO26040322 就有 2 行这样静默填（智云 477.61/661.31 vs 她表 488.64/676.58）。现在每一行都提醒。
- **「超额核销」E4 的上限 = 智云该单交付额**，不是她表应收。她表应收可能是旧值；交付额变**大**时

## 红线（不可改）

- 金额只由脚本算
- 缺逐 SO 金额且无法形成确定顺序时 hold；禁止均分/按比例。逐 SO 金额明确且同一 SO/SOD 的同日多父回款通常逐笔独立落行；已有完整聚合结清行且独立小额父回款合计不超过 1.00 元时保留聚合，不为该尾差单独拆行
