# 金蝶入账 · 业务规则（人话）

数字以同夹 `rules.json` 为准。改口径改 json，再改本说明，不要只改一边。

## 共用

- 账套：总部。不要湖南分公司。
- 记账日期：跑技能当天。
- 产出：`凭证引入_结果.xlsx` + 明细。人过目后自己去金蝶点引入。
- 查档只读。名称先模糊（去有限公司、写两遍、唯一包含），**唯一命中现网档案**才填编码。2–5 候选待确认让人挑；0 命中问斯佳是否新建（不调保存 API）。不编 KH* / GYS*。
- 人名抬头走客户「个人」0582。公安除（申请人=陈霞 且 名称含海淀分局）外归 0386。
- 童睿智、赵贺斌职员挂郑瑞后再核验档案。
- 对话只报笔数、原因类别、路径。

## 销项发票

- 不读下单号、合同号；表内科目列不用。
- 科目：金蝶该客户 1131xx 往来。一条有余额就用；多条开票当月本期借方取大；没有往来 → 待确认。收入 5101+后两位。不用智云业务线。
- 部门：`申请人部门.json` 再经 API 核验。人不在表 → 待确认。
- 借应收（价税合计）/ 贷收入（金额）/ 贷 `21710105`（税额，不挂辅助）
- 约 5 张一记；连续同一家不拆
- 可无发票号、可无组织架构 sheet。组织架构 sheet 不是档案真相源。

## 付款

- 专票：借 `540103` + `21710101` / 贷 `100206`
- 普票：借 `540103` 全额 / 贷 `100206`
- 按台账应付记；票合计可以 ≥ 应付，不能小于
- 部门 `0405`、职员角色「项目总监」是业务配置的查找键；最终写入的部门/职员编码和名称必须由本次 API 档案返回，任一不存在或不唯一即待确认。
- 无档 / 一对多 → `9999` 其他供应商
- 认不清专普 → 待确认

## 收款

- 借 `100201` 不挂辅助
- 贷方科目同销项：金蝶该客户 1131xx 往来。不用表内应收账款编码，不用智云业务线。
- 销售：先回款记录，没有再下单；两个销售 → 待确认并提醒斯佳。表内销售列不用。
- 销售对不上职员档案：仍入账，职员留空。一对多才待确认。
- 约 10 笔一记；连续同一家不拆
- 客户别名见 `客户别名.json`。公安规则同销项（平度等非陈霞海淀 → 0386）。人名走「个人」。
