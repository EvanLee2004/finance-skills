# 金蝶入账 · 业务规则（人话）

数字以同夹 `rules.json` 为准。改口径改 json，再改本说明，不要只改一边。

## 共用

- 账套：总部。不要湖南分公司。
- 记账日期：销项/付款 = 跑技能当天；收款 = 表上收款日。
- 产出：按模块分桌面夹 `金蝶入账_销项_YYYYMMDD` / `金蝶入账_付款_YYYYMMDD` / `金蝶入账_收款_YYYYMMDD`。每夹 `凭证引入_结果.xlsx` + 明细 + `对照说明.md`（只报笔数、原因类别、sheet、起始凭证号、余额表文件名）。人过目后自己去金蝶点引入。
- 凭证号没说时 = 现网当月最大 + 1。查询失败整批停，禁止从 1 起。
- 查档只读。名称先模糊（去有限公司、写两遍、唯一包含），**唯一命中现网档案**才填编码。2–5 候选待确认让人挑；0 命中问斯佳是否新建（不调保存 API）。不编 KH* / GYS*。
- 人名抬头走客户「个人」0582。公安除（申请人=陈霞 且 名称含海淀分局）外归 0386。
- 童睿智、赵贺斌职员挂郑瑞后再核验档案。
- 对话只报笔数、原因类别、路径。

## 销项发票

- 不读下单号、合同号；表内科目列不用。
- 科目：抄客户核算项目余额表（辅助核算=客户，科目 1131）。特殊规则先走（公安除陈霞+海淀外归 0386）。这家只有一条 1131 → 用；两条及以上有期末（或期末都空但本年累计不唯一）→ 待确认问斯佳，禁止取最大；期末都空且本年累计只剩一条 → 用那条；表里没有 → 问是否新建，不编 KH*。收入 5101+后两位。不用智云业务线。
- 取数：认已有「核算项目余额表」xlsx（Downloads 或工作区同结构）；没有则网页引出（OpenAPI 无此报表）。同一客户+科目按月多行时用开票月的上一已过完公历月。
- 部门：同文件「组织架构」优先，没有再用 `申请人部门.json`，再经 API 核验。人不在表 → 待确认。
- 借应收（价税合计）/ 贷收入（金额）/ 贷 `21710105`（税额，不挂辅助）
- 约 5 张一记；连续同一家不拆
- 可无发票号、可无组织架构 sheet。组织架构 sheet 不是档案真相源。

## 付款

- 专票：借 `540103` + `21710101` / 贷 `100206`
- 普票：借 `540103` 全额 / 贷 `100206`
- 按台账应付记；票合计可以 ≥ 应付，不能小于
- 部门 `0405`、职员角色「项目总监」是业务配置的查找键；最终写入的部门/职员编码和名称必须由本次 API 档案返回，任一不存在或不唯一即待确认。
- 无档 / 一对多 → `9999` 其他供应商（一对多不得只 hold）
- 按表头认三列表（第一个 sheet 不是三列表也能认）。不把月底稿「中行付款」「中行流水」当付款。
- PDF 缺票种 / 销售方 / 金额 → 该家待确认。认不清专普 → 待确认

## 收款

- 借 `100201` 不挂辅助
- 贷方科目同销项：抄客户核算项目余额表（`assist_xlsx` + `pick_assist_account`）。不用表内应收账款编码，不用智云业务线，不扫凭证往来窗口。
- 认「中行收款」sheet；不把「中行流水」「组织架构」当业务行。缺部门编码列不整批失败。
- 销售：表上有则用；空则智云回款→下单。两个销售 → 待确认并提醒斯佳。没智云仍出明细，缺销售的行待确认。
- 部门：表上部门编码，否则组织架构按销售，再 `申请人部门.json`。
- 销售对不上职员档案：仍入账，职员留空。一对多才待确认。
- 记账日 = 表上收款日。约 10 笔一记；连续同一家不拆；换日另记。
- 客户别名见 `客户别名.json`。海淀分局不并 0386。平度等其余公安 → 0386。人名走「个人」。
- 8/26 六列表（含部门编码、应收账款编码列）仍可入账，表内应收编码忽略。
