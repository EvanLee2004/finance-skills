# 金蝶入账 · 业务规则（人话）

数字以同夹 `rules.json` 为准。改口径改 json，再改本说明，不要只改一边。

## 共用

- 账套：总部。不要湖南分公司。
- 记账日期：跑技能当天。
- 产出：`凭证引入_结果.xlsx` + 明细。人过目后自己去金蝶点引入。
- 查档只读。精确唯一才填编码。不编 KH* / GYS*。
- 对话只报笔数、原因类别、路径。

## 销项发票

- 借：表里应收账款编码（价税合计）
- 贷：表里主营业务收入编码（金额）
- 贷：`21710105` 销项税（税额，不挂辅助）
- 约 5 张一记；连续同一家不拆
- 可无发票号、可无组织架构 sheet。业务行部门编码只是业务输入，必须在本次 API 档案中唯一核验；不读 sheet 里的组织架构来补档案。
- 缺科目 → 待确认

## 付款

- 专票：借 `540103` + `21710101` / 贷 `100206`
- 普票：借 `540103` 全额 / 贷 `100206`
- 按台账应付记；票合计可以 ≥ 应付，不能小于
- 部门 `0405`、职员角色「项目总监」是业务配置的查找键；最终写入的部门/职员编码和名称必须由本次 API 档案返回，任一不存在或不唯一即待确认。
- 无档 / 一对多 → `9999` 其他供应商
- 认不清专普 → 待确认

## 收款

- 借 `100201` 不挂辅助
- 贷表里应收账款编码
- 约 10 笔一记；连续同一家不拆
- 三户映射见 `客户别名.json`；平度市公安局不映射、待确认
- 销售对不上职员档案：待确认，不得仅写名称或留空后入账。
