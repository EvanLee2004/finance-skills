# 金蝶入账（kingdee-posting）

> 一句话定位：放好一个文件夹，说「销项发票入金蝶 / 付款入金蝶 / 收款入金蝶」→ 技能填官方「凭证引入」表。**人过目后自己去金蝶点引入**；技能不点引入、审核、过账。

## 启动时说

对 opencode 说下面任一句（文件放好，路径一起说）：

- **推荐**：销项发票入金蝶 / 付款入金蝶 / 收款入金蝶
- 也可：琪哥发票入金蝶（仍进销项） / 发票入金蝶 / 供应商付款入金蝶 / 收款入账
- 不是这个：更新财务skills（那是拉代码，不记账）

> 三个模块**分开说**。夹里不止一种表时，技能会问你要跑哪一句。

## 1. 这个技能干嘛

月底把销项发票、供应商付款、银行收款做成金蝶能导入的凭证。以前靠人看表、去档案里对编码、手填引入模板。本技能按表头认是哪一块，缺材料只要缺的那一样；齐了由脚本补科目/销售、算分录，交出引入表。

**科目（斯佳 2026-09-07）**：发票不看「下单号」「合同号」，**不用智云业务线**。特殊规则先走（销项公安除陈霞+海淀外归 0386；收款海淀分局不并 0386）。然后抄**客户核算项目余额表**：这家只有一条 1131 就用；两条期末有数（或期末都空但本年累计不唯一）问斯佳，禁止取最大；期末都空且本年累计只剩一条用那条；表里没有问是否新建，不编 KH*。收入 5101+后两位。OpenAPI 没有这张表，认已有 xlsx 或网页引出。凭证号没说时 = 当前月最大号 + 1，查询失败整批停。收款读**中行收款**；表上销售有则用，空则智云回款→下单；没智云仍出明细。

## 2. 没有它的时候她怎么做（手工流程）

| 步 | 她手工怎么做 | 痛在哪 |
|---|---|---|
| 1 | 打开发票簿 / 付款台账+PDF / 收款表 | 列多、专普要一张张认 |
| 2 | 去金蝶查客户、供应商、职员、部门编码 | 抬头和档案名经常不完全一样 |
| 3 | 按约 5 张（销项）或 10 笔（收款）打成一记；连续同公司不拆 | 硬切会把同一家拆到两记 |
| 4 | 填官方引入模板，再自己去星辰点引入 | 辅助维少填/多填整张失败 |

> 手工大约半天到一天；技能只填表，**引入仍是她点**。

## 3. 现在怎么用（人 + AI 怎么配合）

**她只需要做三件事**：放文件夹 → 说一句话 → 看一眼产出，自己去金蝶引入。

| 谁 | 做什么 |
|---|---|
| **她** | 把当批材料放进一个文件夹，说上面那句 |
| **AI** | 认表 → 调 `scripts/convert.py` → 同一文件夹交出 `凭证引入_结果.xlsx` → **停下** |
| **她** | 看待确认；能转的自己去金蝶「凭证引入」 |
| **AI** | 不点引入、审核、过账 |

**她会看到的话长这样**：

```
这批 30：可入账 28，待确认 2。填好的金蝶表在 <路径>。请您看待确认，再自己去金蝶引入。我没有点引入。
```

**AI 不许做的**：猜公安映射；编客户/供应商编码；把客户名/金额打进对话；要她改文件名；要金蝶登录密码。

### 4.1 三模块现在怎么算

**销项发票**

1. 认表：sheet 叫「发票」或表头同时有单位名称、价税合计。不靠文件名。
2. **不读**「下单号」「合同号」。表里就算填了科目也不用。
3. 公安除陈霞+海淀外归 0386；人名走「个人」。然后按名称对**客户核算项目余额表**（去「有限公司」、写两遍、唯一包含）。表里没有 → 问斯佳是否新建，不调保存 API、不编 KH*。档案 API 只核验编码存在。
4. 科目只抄这张表：这家**只有一条 1131**就用。两条及以上有期末（或期末都空但本年累计不唯一）→ 待确认，禁止取最大。期末都空且本年累计只剩一条 → 用那条。同一客户+科目按月多行时取开票月的上一已过完公历月。收入 = `5101` + 应收后两位。**不用智云业务线，不扫凭证往来窗口。**
5. 没说凭证号时，引入表从当前月 `GET /jdy/v2/fi/voucher` 最大 `number` + 1 起。
6. 部门：同文件「组织架构」优先，没有再用 `申请人部门.json`。职员：`职员挂靠.json`（童睿智/赵贺斌→郑瑞）后再核验档案。人不在表、档案没有或不唯一 → 待确认。
7. 分录：借应收（价税合计）/ 贷收入（金额）/ 贷 21710105（税额，不挂辅助）。约 5 张一记，连续同一家不拆。记账日当天。

**付款**（预处理没改分录）

- 专票：借 540103 + 21710101 / 贷 100206。普票：借 540103 全额 / 贷 100206。
- 认不清专普、票合计小于应付 → 待确认。无档或一对多 → 9999。8/19 记-75 不要再导。

**收款**

1. 认「中行收款」sheet（月底稿第一张是组织架构也没关系）。至少要日期、客户名称、借方（增加）。缺部门编码列不整批失败。表内「应收账款编码」有也不用。
2. 贷方科目：同销项，抄客户核算项目余额表。海淀分局不并 0386。
3. 销售：表上有则用；空则①智云回款记录唯一命中；②回款没有 → 下单页该客户的销售；③下单对上两个销售 → 待确认。没智云仍出明细，缺销售的行待确认。
4. 销售名字对不上金蝶职员：这笔仍入账，职员辅助核算留空。职员档案一对多才 hold。
5. 分录：借 100201（不挂辅助）/ 贷抄来的 1131xx（客户+部门+职员）。记账日=表上收款日。约 10 笔一记，连续同一家不拆，换日另记。

**两套只读闸门**

- 金蝶：`kingdee.local.json` → 当前客户/供应商/部门/职员；销项另要客户核算项目余额表（xlsx 或引出）和当月凭证号。失败或过期缓存不得出表。
- 智云：仅**收款**补空销售。`zhiyun.local.json` → Playwright 登录。失败不得整批空表。销项不登智云。

## 5. 输入 / 输出

| 模块 | 她给什么 | 技能补什么 | 输出 |
|------|----------|------------|------|
| 销项发票 | 发票簿：单位名称、价税合计、申请人（可无发票号、组织架构 sheet、科目列、下单号） | 客户核算项目余额表→应收/收入；组织架构优先否则申请人部门.json | `凭证引入_结果.xlsx` + 明细 + 对照说明 |
| 付款 | 三列表（供应商 / 应付金额本币 / 开户名）+ 一家一个夹，夹里 PDF | 科目固定；无档/一对多→9999 | 同上 |
| 收款 | 月底稿或收款表：日期 / 客户名称 / 借方（增加）（中行收款 sheet；部门编码、表内应收编码可缺） | 贷方抄余额表；表上销售优先，空则回款→下单 | 同上 + 对照说明 |
| 技能自带 | `config/凭证引入空模.xlsx` | | 不要另要空模 |

待确认行进明细、不进引入表。客户、供应商、部门、职员须被本次金蝶只读档案快照唯一核验（收款职员对不上则留空仍入账）。输入表不是档案真相源；组织架构只作部门查找。无金蝶档案：**不出引入表**。销项不要求智云；收款无智云仍出明细。

## 8. 怎么跑

```bash
python3 "<本skill目录>/scripts/convert.py" --inspect --input-dir <目录>
python3 "<本skill目录>/scripts/convert.py" --input-dir <目录> --scene 销项发票
# 付款 / 收款 把 --scene 换成对应模块
# 系统 python3 会自动切到仓内 .venv（里面才有 requests / playwright）
```

可加 `--date YYYY-MM-DD`（销项/付款默认当天；收款行上用表上收款日）。金蝶档案是必需闸门；销项不要求智云；收款智云失败仍出表。`--no-api` 会明确失败。合成测试可加 `--master` / `--lookups` JSON，生产不要用假档案出表。

## 9. 验收口径

- 仓内：`python -m pytest -q skills/kingdee-posting/tests skills/qige-invoice-to-kingdee/tests` 合成用例全绿
- 销项：不读下单号/合同号；科目抄客户核算项目余额表；连续同公司不拆；申请人须在部门表且 API 核验；凭证号默认当月最大 + 1
- 付款：专票拆进项、普票全额；认不清专普 hold
- 收款：读中行收款；表上销售优先、空则回款→下单；双销售 hold；职员对不上留空仍入账；海淀不并 0386；没智云仍出明细
- 无金蝶应用号、档案失败或当月凭证号查不到时不得出引入表。销项/收款不因缺智云失败。
