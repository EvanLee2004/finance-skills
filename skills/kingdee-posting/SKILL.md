# 金蝶入账（销项发票 / 付款 / 收款）

一个技能、三个入口。金额、借贷、科目只由 `scripts/convert.py` 算。销项/收款科目都抄客户核算项目余额表。收款读中行收款；表上销售有则用，空则脚本自己查智云；没智云仍出明细。对话只报笔数和路径，禁止报客户名、金额明细。

后台怎么维护、链接和示意图：先读同夹 `README.md`。

## 0. 本机 json（按入口用，禁止串门）

| 入口 | 只用 | 禁止 |
|------|------|------|
| 销项发票 | `~/.config/finance/kingdee.local.json` | 读 / 验 / 登录 `zhiyun.local.json`；跑九点下单登录脚本；把智云失败当成停表 |
| 付款 | 同上 `kingdee.local.json` | 同上 |
| 收款 | `kingdee.local.json`；表上销售空了才由 **convert.py** 读 `zhiyun.local.json` | 你先手搓登录智云；智云失败整批空表 |

`xingchen.local.json` 是月度损益表的，本技能不要打开。

## 1. 红线

1. 禁止自写 Python 读她的表；只准调本技能 `scripts/convert.py`。
2. 禁止编 KH* / GYS*。销项/收款按客户核算项目余额表对名称（去有限公司/写两遍/唯一包含），表里没有问斯佳是否新建。她点头后 `--create-new-customers` 按现网编号 max+1 建档。付款/收款仍对档案；2–5 个候选从本次档案里挑。销项公安除陈霞+海淀分局外归 0386；收款海淀分局不并 0386。
3. 禁止点金蝶「开始引入 / 审核 / 过账」。
4. 真实 xlsx / PDF / 密钥不进 git。
5. 三个模块不要混在一次「都做了」里；夹里不止一种表时问她跑哪一句。
6. 账套用总部，不要湖南分公司。湖南分序时账抄作业走 `kingdee-gl-import`。
7. 禁止看发票「下单号」「合同号」。禁止用智云业务线或下单额定科目。销项/收款科目只抄客户核算项目余额表（特殊规则先走；一家一条 1131 就用；多条期末有数时按 `申请人科目.json` 拆腿，对不上仍问斯佳；表里没有问是否新建）。不要扫凭证往来窗口、不要当月本期借方取大。不要用部门编码当业务线（王艳玲部门 02、科目 07）。

## 2. 找文件夹、认模块

```bash
python3 "<本skill目录>/scripts/convert.py" --inspect --input-dir <绝对目录>
```

可加 `--scene 销项发票|付款|收款`。缺件会退出非 0，stdout 是 JSON，`ask` 是人话。把 `ask` 原样问她。

按**表头**认，不靠文件名。

## 3. 金蝶闸门（三入口都会停）

不要问金蝶登录密码。本机已有 `~/.config/finance/kingdee.local.json` 就直接用，**不要让她再填、不要去开放平台点重置密钥**。只有文件不存在时才问一次 Client ID / Secret，写入该文件（600）。本机文件已在就直接用，**禁止再问账号密码**。更新财务skills **不得覆盖**本机密钥。AppSecret 会每日刷新，技能用官方 `push_app_authorize` 更新本机文件，只认总部账套。

**只有金蝶这一闸会停整批、不生成引入表**：没有应用号、档案失败（含 errcode 1030002006 且主动获取授权仍失败）、缓存过期、当月凭证号查不到。不能用 `--no-api` 绕过。凭证号禁止 silently 从 1 起。

**销项 / 付款：到此结束。禁止登录智云。禁止因为 `zhiyun.local.json` 存在、缺失或登录失败而停表、改口、让她去核对该文件。**

收款：表上销售空了，`convert.py` 自己会读智云；你不要先手搓登录。文件没有或登录失败 → **仍然出表**，缺销售的行待确认。禁止整批空表。

## 4. 跑转换

```bash
python3 "<本skill目录>/scripts/convert.py" --input-dir <绝对目录> --scene 销项发票
```

付款 / 收款把 `--scene` 换成对应模块。销项这条命令前后都不要跑智云登录。

她说「凭证号从 11 开始 / 从记-11 开始」时加上 `--start-voucher-no 11`。没说就用当前月金蝶已有最大号 + 1。

斯佳点头「这两家新增」时加上 `--create-new-customers`：按现网 3～4 位客户编号 max+1 建档，第一笔用申请人科目。未点头不要加。

没给输出目录时默认按模块写到桌面 `金蝶入账_销项_YYYYMMDD/`、`金蝶入账_付款_YYYYMMDD/`、`金蝶入账_收款_YYYYMMDD/`。系统 `python3` 没有 requests 也没关系：脚本会切到仓内 `.venv`。没有 `.venv` 就按清华镜像装 `requests`（失败再阿里 / 中科大 / 默认源）。不要另开环境管家。**不要**对 macOS 系统 Python 乱装一堆无关库。

默认写出：

- `凭证引入_结果.xlsx`
- `{源文件名}_明细结果.xlsx`
- `对照说明.md`（只报笔数、原因类别、sheet、起始凭证号、余额表文件名）

## 5. 收尾话术

- *「这批 N：可入账 X，待确认 Y。填好的金蝶表在 \<路径\>。请您看待确认，再自己去金蝶引入。我没有点引入。」*
- 待确认只报原因类别和笔数。

## 6. 会变的在哪

| 文件 | 改什么 | 哪个入口用 |
|------|--------|------------|
| `config/rules.json` | 税/银行科目、打包、付款 0405 | 三入口 |
| `config/rules.json` 的 `ar_accounts` | 要查的 1131xx 列表 | 销项 / 收款 |
| `config/申请人部门.json` | 销项申请人 → 部门编码 | 销项 |
| `config/列名别名.json` | 表头别名 | 三入口 |
| `config/客户别名.json` | 三户书面映射 | 三入口 |
| `config/职员挂靠.json` | 童睿智/赵贺斌→郑瑞 | 三入口 |
| `config/申请人科目.json` | 申请人/销售 → 应收后两位（多条 1131 时拆腿） | 销项 / 收款 |
| `config/凭证引入空模.xlsx` | 金蝶换官方模板时整份替换 | 三入口 |
| 本机 `kingdee.local.json` | 开放平台应用号；不进仓 | **三入口都要** |
| 本机 `zhiyun.local.json` | 智云账号；不进仓 | **只有收款，且由 convert.py 读** |
| 本机 `~/.cache/finance/kingdee-master.json` | 只读 API 档案短缓存 | 三入口 |

口径说明：`config/业务规则.md`、`config/场景/`。维护步骤和后台链接：`README.md`。

## 本岗位该主动操心啥

- 夹里同时像销项又像收款 → 停，问跑哪一句。
- 付款认不清专普、票合计小于应付 → 待确认，不要猜税率。
- 收款下单对上两个销售 → 待确认，提醒斯佳单独处理（明细可带候选人名）；职员对不上仍入账、职员留空。没智云仍出明细。本机已有智云号不要再问密码。
- 收款含海淀分局不并 0386。销项公安：陈霞+海淀走自己的档案，其余归 0386。
- 客户档案 2–5 候选 → 停，让人从名单里挑；0 个 → 问斯佳是否新建。她点头「新增」才加 `--create-new-customers`。
- 本机没有金蝶应用号、查档失败、缓存过期或当月凭证号查不到 → 停止，不交空编码/从 1 起的引入表。销项/付款/收款都不要因为没智云就停。
