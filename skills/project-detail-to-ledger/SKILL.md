# 项目明细补录

只处理用户上传的两份 `.xlsx`：项目明细表和盈亏核算表。自动识别表头，不要求用户改文件名、改 sheet 名或打开 Excel；始终保留原件，输出一个新工作簿和一份 JSON 校验报告。

## 标准流程

1. 定位用户上传的两个 `.xlsx` 文件。若文件名不明确，按表头识别：包含 `销售、客户、SO、SOD、业务类别、订单名称、下单日期、整单交付日期、下单数量、单价、交付额/本币、项目经理` 的是项目明细；包含 `销售人员、客户名称、新智云单号、翻译类型、文件名、项目下单日期、项目交付日期、字数统计、价格、应收金额、实收金额、项目经理` 的是盈亏核算表。
2. 先运行 inspect，确认识别到的文件和工作表；不要把原件作为输出路径。
3. 调用本 Skill 的脚本：

   ```powershell
   python "<本 Skill 目录>\scripts\append_project_detail.py" `
     --input-dir "<上传文件所在目录>"
   ```

   也可以在文件不在同一目录时显式传 `--project` 和 `--ledger`。省略 `--output` 时，结果写在盈亏核算表同目录，文件名为 `原文件名_项目明细补录版.xlsx`；同时生成同名 `_补录报告.json`。
4. 用脚本报告和只读回读核验：新增行数、跳过的已存在键、字段映射、数字单元格类型、单号空白、工作簿 ZIP/XML 可读性、原件哈希。输出只报告笔数和路径，不在对话中展开客户名称、订单号或金额明细。

## 固定字段映射

| 盈亏核算表 | 项目明细表 | 处理 |
|---|---|---|
| 销售人员 | 销售 | 原值写入 |
| 客户名称 | 客户 | 原值写入 |
| 单号 | — | 始终留空 |
| 新智云单号 | SO | 原值写入 |
| 翻译类型 | 业务类别 | 原值写入 |
| 文件名 | 订单名称 | 原值写入 |
| 项目下单日期 | 下单日期 | 原值写入 |
| 项目交付日期 | 整单交付日期 | 原值写入 |
| 字数统计 | 下单数量 | 转为数字后写入 |
| 价格 | 单价 | 转为数字后写入 |
| 应收金额 | 交付额/本币 | 转为数字后写入 |
| 实收金额 | SOD | 原值写入 |
| 项目经理 | 项目经理 | 原值写入 |

未列出的盈亏字段不自行填值，不猜测部门、回款、结账状态或公式结果。新增行沿用目标表末尾数据行的单元格样式；原有公式内容保持不变，必要时请求 Excel 重新计算。

## 去重与安全边界

- 以 `SO + SOD` 的规范化组合键判断目标表是否已有记录；已存在的源行跳过并写入报告，不重复追加。
- 缺少 SO 或 SOD 的源行不因缺键而静默丢弃；追加并在报告中保留处理统计。表头缺失、两份文件无法区分或识别出并列候选时停止并说明原因。
- 禁止覆盖用户上传的任一原件；如果默认输出文件已存在，换输出目录或文件名后重跑。
- 不使用浏览器、电脑控制或 Excel GUI；脚本直接处理 OOXML，保留未修改的工作簿部件。
- 不上传、提交或推送工作簿、客户数据、金额数据或凭据。除非用户另行要求，不执行外部系统写入。
