# 甲骨易合并报表与抵销

使用同一个流程完成取数、单体报表汇总、抵销、校验、分册。先读[抵销规则](references/eliminations.md)和[取数操作](references/collection.md)；准备输入和命令时读[执行与证据格式](references/execution.md)。本包复用现有合并报表工具的模板、解析、山东费用分类和Excel生成代码，新增抵销模块；固定工具中心与本原生Skill有独立发布版本。

## 范围与任务

固定YYYYMM、当前用户选定的来源文件和需要取数的主体。总合并=北京本部+全部纳入的子公司+分公司；母公司合并=北京本部+纳入的分公司。母公司汇总不是一个额外单体，不能重复纳入总合并。

本部为HEAD；子公司为CULTURE、SHANGHAI、HUNAN_TECH、JINAN；分公司为SHANDONG、HUNAN_BRANCH、SICHUAN。全称与别名以包内templates/companies.json、scripts/engine.py为准。八家三表共24份来源，记录逐公司逐表的实际纳入范围。缺整表不能补零；山东省略的无数据标准项目可按既有映射补零。模板统一采用本部，异常非零项目无法映射时标记待核实。

用户请求制作报表，授权读取选定材料、必要的只读金蝶取数及生成新交付文件；不含金蝶引入、审核、过账、财务原件覆盖或历史任务重跑。制作或安装Skill本身不启动财务任务。

## 1. 取得并核对来源

所有金蝶取数均使用Playwright无头浏览器（headless=True），包括三张单体报表及三类抵销明细；具体运行要求见references/collection.md。

金蝶五账套取三表；山东、四川、济南使用用户提供的外部报表。验证每份文件的公司、月份、金额单位和口径；保存文件SHA256与来源记录。资产负债表勾选重分类、不勾选应交税费重分类，选完期间、开关后点击报表内查询或右上角刷新并再次验证期间；浏览器整页刷新会回到最新期间。

抵销只在北京本部账套取数，按references/collection.md取得逐公司证据。以本次金蝶查询为准，样例底稿仅用于理解格式和比对；不复制历史抵销常数，不为对齐样例擅自调整金额。

完成条件：每项材料均有期间、主体、来源与状态；来源冲突解决或明确标记，抵销证据缺失项列明。

## 2. 计算与生成

将证据按references/execution.md结构保存为本次正式业务核验材料。按[AI标准调用协议](references/ai-interface.md)先执行scripts/skill_cli.py check，再执行run，统一执行原工具的字段映射、山东管理费用全部转营业成本、两套范围汇总和抵销。金额用Decimal；逐公司÷1.06四舍五入到分，再汇总。摘要筛选、科目遍历和凭证证据由Agent核对，金额运算和公式生成交给脚本。

母公司利润表保留正常汇总及山东费用分类，暂不做利润抵销。两套资产负债表都抵销其他应收与其他应付的期末数；两套现金流都按自身范围的内部流出合计，同时抵减经营活动其他现金的收到与支付；本月及累计分别计算。金额以当期金蝶为准，测试底稿的300元差异不作补差。本部与其他公司单体来源区保持原金额，抵销只作用于右侧汇总区及依赖合计。

完成条件：脚本成功、六表生成、来源未改、全部抵销项有规则与来源引用；有缺项的文件必须保持部分或待核实状态。

## 3. 验证与交付

检查源数据与公司区、单体与汇总范围、抵销前后公式及缓存；验证两套资产负债表平衡、现金流净增加额与期初期末关系，以及母公司利润表未被抵销。所有合计汇总单元格用公式，明细金额为数值。金额字体18号，金额列宽30，负数普通黑字，不加红色格式。

交付一份六表完整底稿、一个含三张合并表的分册、一个含三张母公司表的分册，以及来源/抵销核验JSON。Excel只留六张主表或对应三表，不额外保留单体sheet；各公司数据仍在主表横向区域。拆分在抵销完成之后执行，分册公式、显示值与完整底稿一致且无外链。删除本次临时脚本、截图和中间文件，仅保留正式交付、原始业务来源及必要核验记录；不要删除既有用户材料或运行回滚文件。

报告实际完成范围及差异。代码测试、Skill安装、真实金蝶取数、财务报表验收分别说明，不能互相替代。
